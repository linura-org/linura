# S21-3 physical backlight enrollment and safe-minimum acceptance

**Status:** Procedure only; **no maintained physical workstation is enrolled or qualified by this document**.
**Scope:** `arch-hyprland-v1`, native Linux backlight (not software gamma, DDC/CI or VM emulation).
**Governance:** [ADR 0046](../adr/0046-authenticated-user-session-execution.md),
[ADR 0045](../adr/0045-s21-workstation-device-authority.md) and the
[S21-3 ledger](v0.10.0-s21-3-backlight.md). The existing Q11 maintained-hardware
acceptance remains the authoritative release gate, not this checklist.

This procedure makes hardware ownership, minimum visibility and independent
recovery **testable prerequisites**. It does not authorize an unregistered
operation or construct a `BacklightDeviceGeneration` credential from
untrusted JSON. All observation and handoff evidence must be independently
checked by qualified native components before any Control registration.

## 1. Admission prerequisites

Require an actual, maintained physical workstation under the qualifying
operator's control. Before attempting *any* brightness mutation, capture and
independently validate:

- Exact source commit and release/profile revisions, immutable package
  inventory and execution substrate. Record whether the host is physical,
  virtualized, a container or nested; only real hardware can qualify Level C.
- Kernel boot UUID; active local Wayland session ID and creation generation;
  original numeric non-root UID; native seat, logind unique bus owner and
  systemd/logind versions. Show the caller's actual system-bus UID/PID and
  session membership independently of user-supplied Actor metadata.
- GPU PCI identity, active kernel driver and version, DRM card and connector
  identity/generation, supported panel path and connected/active displays,
  udev device genealogy, native backlight class/type/name/canonical path and
  source generation. Prove the backlight belongs to the target panel and seat.
  A kernel backlight symlink, inode, numeric ID, UUID string or eDP name
  **alone** is insufficient evidence of physical lineage.
- Native `max_brightness`, `brightness`, `actual_brightness` and
  `bl_power` obtained from independently trusted native reads before,
  during and after each test; reject absent actual state, multiple ambiguous
  physical candidates, unsupported power, unstable values or inconsistent
  source generations.
- A separately accessible **recovery operator and mechanism**, tested
  *before* deliberate dimming. Recovery must not rely on the display being
  calibrated or on an invisible QML confirmation. Examples may include an
  independently visible external output with trusted recovery access, or
  separately controlled out-of-band console/hardware restore. Do not assume
  SSH, another UI or a keyboard shortcut is sufficient merely because it
  works when the panel is visible; prove actual recovery under the
  supported profile and preserve Linura's default security posture.
- An independently reviewed test plan with a visible-access stop condition,
  original native setting and exact restoration method. Never disable secure
  session locking, elevate a root D-Bus brightness caller, enable sysfs
  mutation via Linura, bypass policy or fall back to gamma to make the test pass.

**Fail closed:** if the operator cannot positively attest all prerequisites,
record `unsupported/unqualified` and run read-only discovery only. Do not
approximate a safe minimum as `1`, a percentage, a driver default, or a
caller-chosen value.

## 2. Calibrate an actually visible floor

Calibration must be supervised on the physical machine, after the separate
recovery path has been demonstrated. Preserve an unchanged independent display
or equivalent external recovery channel throughout. For each exact
GPU/driver/panel/backlight/seat/max configuration:

1. Capture a timestamped, independently read **original** stable
   requested/actual brightness and supported power state; both original
   values must be at or above the eventual accepted minimum. An already dark,
   subminimum or unsettled baseline is a blocker, not permission to try a
   higher unqualified Control mutation.
2. Under an independently approved physical qualification procedure,
   establish a conservatively visible **strictly positive integer native
   minimum**, observing the actual native state at every step. Use direct
   human visibility assessment and a separate independent measurement where
   available; distinguish the operator's visual judgment, device sensor,
   requested setting, actual kernel fact and evidence of display illumination.
3. Reobserve a fresh actual value *after* any controlled calibration step,
   preserving exact kernel/logind/device/seat generations. Do not classify
   a D-Bus reply, slider, screenshot or requested register value as actual
   physical success. Any changed generation, provider service, power,
   maximum, session, connector or ambiguous correspondence invalidates the
   calibration for current authority.
4. Restore the original visible level through the independently tested
   recovery path; separately verify the restored actual brightness. A
   restoration observation does not itself grant Linura permission to
   execute a compensating write.
5. Repeat the test and recovery with the agreed supported configurations,
   including the sole-visible-output configuration. If any tested transition
   can remove reliable visible access, **do not enroll** that configuration.
   Never promote a universal minimum across different panels or drivers.

A successful calibration produces **evidence** for a *specific qualified
configuration*, not a globally reusable brightness number or automatic
authorization. A safe minimum is invalidated by hardware substitution,
driver/firmware change, panel changes, maximum change, seat/topology changes,
loss of external recovery, or an expired qualification revision.

## 3. Protected native user-session authority

The release test must prove the final logind
`org.freedesktop.login1.Session.SetBrightness` call is made **by the
attested original non-root user-session subject** after Control's signed,
single-use durable dispatch reservation. A root-owned S17 executor's
`SetBrightness` call is forbidden for this purpose because it is not
the original user's logind privilege.

Require denial evidence for root/foreign/same-UID-other-session substitutions,
recycled PID or logind owner, replaced worker invocation, forged D-Bus sender,
untrusted method/subsystem/path, extra payload keys, lowered risk and
missing/expired approval. The receiving endpoint must be protected against
same-UID code injection, token theft, channel replacement, duplicate handoff
and delayed delivery. Qualified worker/session channel and device generation
must still match at the last possible pre-dispatch check.

**Without an independently qualified worker and protected one-use handoff,
run the read-only candidate path and fail any attempted managed mutation.**

## 4. Indeterminate outcome and visible-access fault matrix

Record native state, Control transaction generation, audit/evidence identity,
worker invocation, kernel/logind generations, user session, actual native
brightness and the independent recovery result for each fault.

| Exercise | Required evidence |
| --- | --- |
| Duplicate request or replay after timeout | One durable attempt only; no second native dispatch |
| Crash after persisted reservation, before reply | `Indeterminate` retained across restart; observation-only recovery |
| Lost logind reply after possible effect | Independent new requested/actual readings; no inference from reply |
| Competing native brightness writer | Precondition or verification rejects changed native level |
| Swapped/recycled sysfs object or device | Exact generation mismatch blocks use of old qualification |
| logind owner restart, session switch, new boot | Previous caller/resource/approval invalidated before native call |
| Panel hotplug or DRM topology change | Safety mapping invalidated; sole-output visibility preserved |
| Below-minimum original or target | No managed brightness dispatch, no dark "restoration" acceptance |
| Independently inaccessible or failed recovery | Unsupported; no Level C/Q11 acceptance |
| Unavailable physical device or missing actual value | Unsupported; no gamma/DDC or mocked fallback |

The qualifying machine must **not** create a synthetic successful result
merely to unblock CI. Real fault injection requires prior approved recovery
controls. Q11 evidence must be retained under the existing independently
verified, source-bound evidence publication rules; a video can corroborate
a run but is not the correctness oracle.

## 5. Required evidence and acceptance decision

A reviewed physical qualification record must identify, at minimum:

- Source SHA and exact-run ID; qualifying machine/fixture ID and physical
  substrate proofs; native host/driver/logind/provider versions.
- Trusted boot/session/seat/original-caller evidence, kernel backlight and
  DRM/panel lineage, identity generation, tested maximum, measured actual
  baseline and proposed minimum.
- Independent calibration provenance (operator, method, timestamps,
  measurement uncertainty), repeatability and original-value restoration.
- Independently exercised out-of-band recovery mechanism and outcome,
  including the failure case where the screen cannot display an interactive
  confirmation.
- Signed/digested immutable evidence references and independent verifier
  conclusion for every mandatory Level C case, including all failures.
- Exact reviewed S21-2 display topology integration, active S17 secure-lock
  protection, one-use native user-session execution and complete durable
  post-effect verification.

Only the existing trusted Q11 release-acceptance authority may promote
hardware support. This document's existence, a parsed profile, a maintainer's
checkbox, synthetic VM tests, a manually entered device-generation UUID, or
this PR's green regression CI **does not** create permission to write.
