# v0.10 S21 qualification — display, brightness, power and removable media

**Status:** Proposed; native effects, physical hardware and release support not qualified.
**Profile:** `arch-hyprland-v1` (development).
**Authority:** [ADR 0045](../adr/0045-s21-workstation-device-authority.md), [S17 ADR 0042](../adr/0042-s17-session-security-and-power-authority.md).
**Prerequisite:** S17 accepted security and power authority, including native lock coverage.

## Evidence ownership

This document specializes the existing [v0.10 qualification](v0.10.0.md) Q9 provider, Q10 convergence, Q11 maintained hardware, Q12 recovery and Q13–Q14 security/inherited gates. It does not create an alternative support ledger. Every native claim must bind source SHA, pinned Arch/provider versions, native object/subject identities, an independently observed postcondition and applicable negative cases. Executor receipts, screenshots, videos and mocked state never substitute for the verification oracle.

## Required positive and negative cases

| Domain | Required execution and verification | Failure and adversarial rejection |
| --- | --- | --- |
| Display | Exact live Hyprland compositor/boot/session, complete selected-output topology, native mode/refresh/scale/transform, last-good rollback and independently re-observed state | Invalid layout, duplicate connector, stale generation, hotplug, lost sole visible output, partial apply, timed-out confirmation, compositor crash and any S17 locked-output coverage gap |
| Backlight | Actual active-seat native device, `max_brightness`, supported minimum, deterministic native value mapping, independently verified resulting brightness | Foreign seat/UID, changed max, path reuse, removal, denied logind API, unsupported device, screen blackout, software gamma substituted as hardware |
| Removable media | UDisks2 drive/block/filesystem lineage, source/owner generation, supported mount and unmount, Polkit subject, verified mountpoints and independently qualified drive eject or power-off | Busy mount, sibling still mounted, unapproved mount options/path, foreign subject, recycled block/bus path, hot-unplug, service loss, delayed reply and repeated eject |
| Power | Reuse S17 session-bound `Can*` and inhibitor observation and the same typed managed transition; equivalent GUI/CLI receipt | Root subject permission laundering, `block-weak` bypass, other sessions, late inhibitor, stale lock generation, unlocked suspend, duplicate dispatch |
| Interfaces | Control Center, Quick Settings, keyboard/OSD, CLI/SDK and no-AI pathways show the same canonical state, operation and verification | Cached/optimistic success, accessibility/focus/overlay leak, model authority escalation, client restart replay, unavailable/stale state hidden |

## Unit, contract and security qualification

Build readiness precedes native qualification. Reuse `core`/`shell`/`editor` for
general development and security-owner prerequisites; verify the complete
native security-owner CMake/CTest build separately. The standalone
`hyprland-build` inventory and `contracts/s21-hyprland-build-environment.toml`
cover the source-pinned compositor SDK, including GLES3/EGL and Glaze. Its
actual private-header compilation, whole-compositor linking and live integration
identity must be verified in S21-2. The static source integration does not use a
dynamic plugin ABI. None of these build results imply native display safety.
The shared live integration identity includes the exact upstream hook recipe;
qualification must reject recipe-mismatched builds even at the same upstream
revision. Runtime evidence must still bind the actual qualified binary and SDK.

The existing automated workflow requires the exact-source compositor build
before its native session lane. A closed, attempt-bound build candidate retains
only the binary, compiled integration identity and public source/SDK metadata.
It is an ordinary unqualified build artifact, never a reusable substrate cache
or execution proof. The runtime verifies source, recipe, contracts and retained
bytes; its disposable guest compares the freshly built owner's native identity,
checks installed packages against the pinned SDK and replaces the stopped
reference compositor at the existing immutable executable path. Bootstrap
additionally binds the actual executing inode and binary digest. The original
shell cases still run before that replacement, and all native S17 cases remain
mandatory. Missing, stale or incompatible candidate bytes stop the lane; there
is no fallback to the reference compositor for native session qualification.
Executing those existing cases on the candidate does not qualify the missing
S21 display effects, independent restoration or compositor-restart recovery.

Runtime package presence comes from the existing canonical shell-runtime
substrate contract, which is also bound into the candidate source metadata.
The SDK's installation list includes build-only Git/Meson/protocol tools and
must not become a requirement to install those into the runtime. Every installed
runtime package still needs the exact version in the full frozen SDK inventory;
missing required runtime packages, different versions and additional unbound
providers remain failures. Both contracts must identify the same architecture,
base image and archive snapshot. Tests omit the actual build-only tool set and
reject removal of each required runtime package independently.

S21-2 must extend the existing Level A Arch/Hyprland route with real display
mutation, timed-out/lost-client restoration, restart reconciliation, hotplug and
S17 output-lock coverage. Complete Control Center/Quick Settings/display UI is
S21-6; cross-domain integration and maintained physical acceptance stay
S21-7/release work. These boundaries do not postpone display-specific native
qualification until S21-7 or replace the existing Level A/B/C definitions.

- Verify trusted operation registration, provider/resource/risk floors, subject and generation binding, bounded postcondition, positive and negative typed-plan shape; reject ambient target selection, unknown operations and client-supplied downgrades.
- For managed effects, assert durable prepare and ambiguity reservation before any privileged handoff, exact independent verification after effect, and observation-only reconciliation for uncertain dispatch. Failures in audit/registration/provider cannot silently become success.
- Model multi-output topology with lock generation, output hotplug, partial mutation and last-known-good recovery; verify the recovery path is available without the affected QML surface.
- Cover logind seat/owner swaps, real backlight absence, hardware bounds/rounding and rejected fallbacks; verify actual native state rather than displayed slider position.
- Cover UDisks2 sibling-device relationships, mount state, Polkit identity, busy files, delayed/unavailable service, media removal and non-replayed indeterminate power-off.
- Require keyboard/pointer, semantic accessibility, reduced motion, HiDPI/multiple output, secret-safe notifications and QML focus-region tests for every supported control.

## Acceptance levels

### Implemented display component checks

The Rust component suites exercise typed native JSON and duplicate-field
rejection; disabled-output modes, mirroring and DPMS; bounded IPC reply size and
timeouts; closed transforms, geometry bounds and canonical layout decoding;
canonical-envelope identity/freshness/schema validation; separate session/seat
and exact output-coverage review; request/lock-target idempotency; and independent
postcondition ordering, generation and full-layout checks. These fixtures do not
execute a compositor change, verify autonomous recovery or prove S17
reconfiguration coverage. The managed display operation is registered and
draft protected-journal phase records/controller code exist, but no complete
native transaction port, independently armed rollback or public apply path
is activated. The private prepared transaction port now connects Control's sealed
effect to the independently admitted root session executor, strict Rust native
validation and one original-connection owner/compositor apply. Production status
can observe/reconcile exact retained dispatch history after adapter restart,
without replay or continuation. Public begin/confirm/revert remain unsupported;
the private handoff, protected decisions and compositor-loss recovery still need
complete native acceptance. The native owner and Linux adapter implement the bounded
topology/coverage probe. Wayland wire fixtures cover head-name reuse, missing facts, duplicate names,
mode removal and inventory exhaustion without creating an output configuration.
The real pinned compositor must still independently qualify those observations,
per-output coverage and identity/freshness behavior. Missing bindings fail closed.
Native execution/recovery, hotplug generation attestation, representative real
Hyprland multioutput exercises and exact-head qualification remain required.

In-process compensation additionally retains the prior overlay ownership and
native automatic mode/scale/position semantics. Numeric geometry alone cannot
retire restoration: the compositor checks that previous ownership resumed and
that the underlying owned rule semantics did not change. Unrelated current
color/ICC/VRR/reservation settings remain live. Components and exact-SDK rule
tests exercise this distinction; the checkpoint is volatile and does not satisfy
durable last-known-good recovery after compositor termination.

### Runtime levels

**A — automated exact-source Arch/Hyprland VM:** mandatory deterministic real compositor/UDisks2 native mechanics, source/guest digest, safe failures, adversarial assertions and retained Wayland recording (not the correctness oracle). Virtual outputs, loop devices and mock backlights prove only explicitly scoped fixture behavior.

**B — interactive VM:** same pinned source/substrate with optional interactive viewing and recording. Does not replace A or C.

**C — maintained physical workstation/Q11:** independently nonvirtual, source/hardware-bound and complete Q11 case set, including real GPU/DRM/multi-output/HiDPI/input/a11y, hardware backlight where supported, physical eject and drive power-off where separately claimed, native provider versions, security locks and recovery. No simulated backlight or virtual drive may be reported as real hardware qualification. S21 may supply domain evidence ahead of Q11 but cannot mark `interactive_workstation.evidence_ready` true.

## Release gates

[Security qualification](v0.10.0-s21-security.md) defines adversarial prerequisites. All existing S17, v0.4/v0.6/v0.9/v0.10, security, CodeQL, immutable evidence and regression gates remain in force. Support, S17/S21 ledger closure and physical readiness are separate protected release decisions. Documentation and a qualified *component* cannot assert entire S21 or v0.10 completion.
