# v0.6.0 release-preparation review

**Status:** open until final compacted implementation source and protected release proof satisfy every release blocker.
**Claim class:** Experimental
**Supported platform profiles:** none

This review is the final pre-publication cross-check between the v0.6 milestone, architecture/security decisions, implementation boundaries, permanent qualification, component maturity and release-control chain. It intentionally distinguishes **implemented** from **proven on the final release source**.

## Review rule

A checked box in source documentation is not itself acceptance evidence. Terminal release status comes only from exact-source workflow/release artifacts after the candidate history is final.

PR #74 may remain a development/draft implementation branch while this documentation is reviewed. Its eventual history compaction changes the candidate SHA and therefore requires fresh exact-head qualification afterward.

## Milestone boundary review

The v0.6 release claim must remain exactly:

- one bounded Experimental managed external effect;
- canonical `linura-managed-*.service` systemd units;
- desired state exactly `active` or `inactive`;
- native systemd `StartUnit` / `StopUnit`;
- complete eleven-stage lifecycle.

The release must **not** absorb:

- generic `apply`;
- arbitrary shell/commands;
- generic systemd method forwarding;
- package/file/network/storage/firewall/user/container/VM mutation;
- agent/model execution authority;
- persistent intent/Library work from v0.7;
- agent interpretation from v0.8;
- First Boot/supported reference environment/hardware from v0.9;
- Control Center/Shell/general managed configuration from later milestones;
- Stable API or supported-distribution/hardware claims.

**Review status:** architecture/docs must be rejected if any of those future scopes is presented as current v0.6 capability.
