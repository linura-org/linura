# v0.10 S21-5 — power experience and bounded idle behavior

**Implementation status:** the read-only compositor input advisory, independently authenticated native logind idle observation, own-user D-Bus diagnostics and durable per-UID advisory threshold are implemented in source. Automatic idle effects, an authoritative multi-provider idle-to-effect policy, complete physical native acceptance and physical Q11 are **not implemented or qualified**. The versioned, Control-owned advisory preference remains independent of S17 authentication/approval records; implemented source is not by itself evidence of native acceptance.
**Authority:** S17 (ADR 0042) and S21 (ADR 0045). This document narrows the S21-5 deliverable without declaring S17 or S21 complete.

## Existing implementation / no second executor

The shipped `SessionController` and `plugins/power/PowerControls.qml` already expose manually initiated own-session lock, suspend, logout, reboot and power-off. They use the same S17 `Authority1` and Control managed operations, with action-specific native authentication, a presecured session, durable request tracking, an independently validated receipt and observation-only recovery. Neither PowerControls nor future idle UI may introduce an alternative D-Bus executor, call `systemctl`, forge an approval or treat a successful native reply as current state.

The source-of-truth for proposed S21-5 safety restrictions is `contracts/v010-s21-power-idle.toml`. It is deliberately inert: it is not an operation registry, timer, policy grant or runtime component. Automatic transitions must remain disabled while these acceptance requirements are outstanding.

## Implemented compositor input advisory

The supported first-party Quickshell host explicitly imports `Quickshell.Wayland` and observes `IdleMonitor` at the Control-verified advisory threshold (default 300 seconds, 60–3600 seconds), with `respectInhibitors: true`, only while Quick Settings is visible and the preference has passed native own-session validation. A failed preference query disables the monitor rather than falling back to an uncontrolled timeout. The signal is projected through the existing Session Controls / Power Controls presentation components as accessible plain text. A true result is worded as a **compositor-reported inactivity hint**, never as a power/lock/approval fact; a false result is deliberately described as *no reported threshold*, not proof of activity. The Quickshell monitor requires `ext-idle-notify-v1`; unsupported compositor protocols or unavailable Wayland state are **not** accepted as fresh authoritative evidence. Quickshell exposes no positive protocol-availability proof through this boolean, so an unreported threshold must remain ambiguous rather than imply the user is active. No `onIsIdleChanged` dispatch, provider command, timer-driven lock, inhibitor override or automatic transition is added. The existing SessionController remains the sole action client.

This is a strictly advisory display capability. It does not fulfill a multi-provider authoritative idle policy or an automatic secure action policy. The authenticated native logind observation and durable advisory preferences are implemented independently below; neither authorizes effects.

## Independently bound native logind idle fact

The logind adapter now advertises the read-only `session.idle.observe` capability. It obtains exact-session `IdleHint` and `IdleSinceHintMonotonic` from the kernel-peer-attested root logind owner through a bounded system-bus response. It rejects missing/wrong types, clock rollback, impossible timestamps, changes between the initial and final samples, replaced logind owners, boot changes or recycled session object identity. The returned native `ObservationEnvelope` carries the normal authority/freshness/provenance fields and binds the new values to the exact session epoch. The idle hint is **not** a compositor-wide inactivity signal, proof of currently protected lock, or authorization for automatic effects.

The native observation is exposed via `Authority1.GetOwnNativeIdleStatus`, which derives the caller from the authenticated system-bus sender and matches the exact active, local owner session and seat against a separate native observation. It returns only an epoch, seat, bool and monotonic last-change timestamp. The nonprivileged session controller displays this as a historical, read-only status alongside the compositor hint; a malformed reply or denied native predicate returns unavailable rather than an optimistic result.

## Durable advisory preferences

A separate, versioned `SqliteIdleAdvisoryPreferenceStore` persists only a per-UID inactivity **display threshold** (1–60 minutes, whole minutes) plus an optimistic revision. The store is private to the authority daemon, uses the protected StateDirectory, a distinct secret integrity key, SQLite WAL with full synchronous commit, application/schema verification, bounded rows, and an integrity tag over the full canonical retained set. Unexpected schema, missing records, corrupt rows, substituted keys or stale compare-and-swap revisions fail closed. It has no power/lock executor method, approval record, risk classification or automatic dispatch.

The `GetOwnIdleAdvisoryPreference` and `SetOwnIdleAdvisoryPreference` API derives the caller from the transport and freshly validates its own native session identity before reading or writing the non-authorizing preference. The ordinary UI offers explicit fixed threshold presets and requires a user click; a write reply is not treated as final preference truth, and a subsequent read verifies the current setting. Lost or conflicting writes are not replayed. The compositor advisory monitor remains inactive when the preference cannot be retrieved.

This preference is intentionally persistent **per UID** across login sessions; the ability to edit it is bound to a current active, local session. Cross-seat authorization and power effects are not derived from persistence.

This native adapter capability is not yet an accepted multi-provider idle authority decision. Its consumer must additionally validate authenticated own-user/seat/active-session scope; the future Control policy/reconciler cannot elevate a native hint into an effect permit without the ordinary S17 authorization lifecycle.

## Bounded idle semantics

1. **Observe, do not authorize.** A native idle hint is advisory, not a transition permit, proof of secure-lock coverage or evidence that sleep occurred. Future observation must be bound to fresh boot, UID, foreground logind session/seat, trusted owner and monotonic generation. Reconnect, suspend/resume, seat switch, wake, hotplug or service replacement invalidates stale idle samples and pending drafts.
2. **Explicit policy only.** A validated, versioned per-session user preference may eventually configure notification/preview behavior. It cannot carry authorization, risk downgrades, arbitrary commands, Polkit decisions or unbounded native parameters. No implicit upgrade from a display timeout to secure lock or suspension.
3. **No unattended authorization.** Background timers and UI close/restart cannot answer S17 native approval, perform logout, reboot, shutdown or invoke direct logind sleep. Any future automatic secure lock must be a **new separately qualified S17-compatible authority decision**, not an invocation of the interactive `ConvergeSessionLock` prompt on behalf of an absent owner. Automatic suspend needs an independently reviewed policy that preserves secure-lock output coverage, other sessions, inhibitors including `block-weak`, owner subject and no replay. Until qualified, both remain unsupported.
4. **No covert output blackout.** Blank, DPMS-off, compositor output disable, backlight dim and sleep are distinct effects. Their future implementation depends on S21-2 display recovery and S21-3 hardware backlight attestation as applicable. Loss of the last recoverable visible/locked output, uncertain hotplug or unsuccessful first frame must not be silently accepted.
5. **One request, one history.** Manual actions retain the exact request before effect, display blocked/pending/indeterminate separately from verified completion, and never resume an abandoned transition after restart. A lost reply requires observation-only reconciliation; neither a UI button nor background idle tick may replay it.

## User experience / qualification

Power controls must provide exact action labels, explicit risk and native-authentication expectations, no-AI operation, keyboard/pointer parity, accessible semantics, reduced-motion and HiDPI/multi-output behavior. UI interruption, disconnected Control, stale session, pending request, missing local durable tracking or uncertain native coverage disable new effects. A status view is not a substitute for independent machine-state observation. The currently shipped panel explicitly discloses that it **does not** enable automatic idle effects.

The source now includes a read-only native logind provider, authenticated own-session diagnostics, a durable **per-UID advisory preference** with revision CAS, and Qt/CTest, Rust and static adversarial checks. These checks do not establish physical device behavior. Before making any Level A or physical acceptance claim, require exact-head Arch/Hyprland/Quickshell evidence and relevant Q11 hardware evidence; test idle-input races, seat and bus-owner swaps, wake/restart, inhibitors, secure lock and hotplug at the applicable native level. Before proposing an automatic lock, display or power effect, separately design, review and qualify an S17-compatible authorization and recovery policy. No missing acceptance step may be bypassed, and no currently implemented hint or threshold is an effect permit.

**S21-5 scope boundary:** S21-2 display, S21-3 brightness, S21-4 UDisks2, S21-6 multi-surface convergence and S21-7 integrated native/hardware acceptance remain separately tracked. S17 remains the sole power authority.
