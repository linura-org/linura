# S21-2 compositor-loss restoration — implementation and acceptance boundary

**Status:** Private replacement restoration, independent restoration proof and
original-restoration Root/native final retirement with Control `ReleasedCurrent`
bookkeeping and a separately prepared same-invocation successor handoff are
implemented in source. Their real native acceptance remains outstanding.
Ordinary first-handoff/grant/verification source work is implemented; its durable
completion and ordered fence retirement remain unfinished. Cross-invocation adoption, Stage 5 lifecycle management
and complete native acceptance remain **unfinished**; production public mutations
remain unsupported.
**Scope:** Native display mutation and its restoration on the exact pinned Hyprland
source. This document does not create a second Control authority, a support
claim, a device credential or a new release gate.

## Failure to address

The compositor saves its live monitor-rule semantics and overlay ownership in
`RuleOverlayCheckpoint` memory. The root executor now durably reserves an
immutable original-rule/overlay preimage before native apply. Normal teardown
can compensate, but process death (including SIGKILL, OOM kill, fatal compositor
error or power loss) destroys the live checkpoint, transaction clock, native
frame receipts and compositor-owned power inhibitor. A retained preimage cannot
reconstruct these lifetimes or authorize a write. A later compositor instance is not the same
native owner, even if EDID, connector names, numeric modes and output handles
look identical. The authenticated Control journal retains historical
comparison evidence, **not** the original native rules or a command to apply.

Therefore a matching screen layout or successful new lock acquisition is not
proof that the old native transaction restored its previous *ownership* or
automatic monitor-rule semantics. No public Begin/Confirm/Revert path may
become supported on this evidence alone.

## Required implementation boundaries

1. **Before-effect durable reservation.** Control durably reserves the exact
   original principal, request, transaction, boot/session/compositor, complete
   source-pinned output identity, original confirmation deadlines and
   immutable intent. The restoration preimage, including each original
   native-owned monitor-rule field, rule selector/precedence and prior
   Linura overlay ownership, must be recorded durably **before** the first
   native write. An opaque digest cannot reconstruct this preimage.
2. **Private, independently owned recovery record.** Store only bounded
   validated fields in a root-controlled, atomic, crash-consistent private
   record with explicit schema/version, integrity, source/build identity,
   exclusive owner, file-system durability and replay-protected transition
   history. Do not serialize raw provider pointers, unbounded strings,
   shell commands, user-authentication material or executor capabilities.
   A partially written, corrupted, missing or substituted record stays
   indeterminate; it must never be treated as an empty/retired attempt.
3. **Survive compositor loss outside the compositor.** An independently
   supervised recovery coordinator must observe process termination and
   generation replacement, retain the unresolved fence and deny new effects.
   It cannot depend on the dead UI/Wayland connection, on the old
   compositor-owned inhibitor, or on an agent's retry. New compositor startup
   must not implicitly erase old unresolved reservations.
   Admission before the first ordinary frame must serialize against prepared
   display reservations and bind the actual new compositor lifetime, boot,
   session and pinned source. A one-time "history is empty" Boolean followed by
   unguarded startup has a race with an old invocation's concurrent dispatch;
   it is not a startup fence. Unknown supervision or a changed admission epoch
   must retain opaque/input protection, without acquiring or releasing S17 lock
   authority merely because a display request exists.
4. **Prepare safely in the new invocation.** Authenticate the exact current
   boot/logind session/seat, source-pinned compositor binary and native
   output lineage; independently observe kernel/DRM outputs and verify that
   applying the retained preimage is safe. A connector-name or EDID match
   alone must not authorize restoration. Unexpected hotplug, changed native
   rules, ambiguous outputs, missing visible root, stale generation,
   unavailable recovery supervision or lost lock coverage require refusal
   and an external/operator recovery path.
5. **Single-use restoration.** Permit exactly one separately authenticated,
   purpose-bound restoration of the retained preimage (never replay the
   desired layout). Atomically reserve that attempt *before* issuing effects.
   Retain the safety fence through partial success, response loss, timeout
   and service death. A second restore is not implied by a missing reply.
6. **Independent terminal verification.** Require newly acquired
   per-output frame/disable evidence, actual native rule and overlay ownership
   restoration, surviving visible root and independently observed kernel-output
   continuity. Re-read identity after effect. A restored geometry with an
   explicit override still installed is insufficient. Only Control may retire
   the durable reservation after verified terminal history is recorded.
7. **Never promote historical evidence.** Observations and old journals can
   explain or reconcile an indeterminate operation; they cannot grant
   admission, fabricate fresh native proof, renew a deadline, authorize
   cross-invocation replay, release an S17 security fence or return a new
   user-visible success without current verification.

## Exact-head acceptance matrix

| Case | Required oracle | Required failure behavior |
| --- | --- | --- |
| Locked/unlocked two-output Apply → Keep | Real pinned compositor; separate physical input and fresh first frame on **each** enabled output | Missing hardware-completed frame or expired choice leaves the operation pending/indeterminate |
| Apply → explicit Revert and expiry | Actual baseline numeric layout **and** original rule/overlay semantics | Lost reply cannot initiate a second restoration or grant a Keep |
| Output disable, mirror, scale and transform | Independent root remains powered and visible; exact output lineage and protected frame epochs | Stale generations, DPMS drift or last-visible loss deny before effect |
| SIGKILL during each native write phase | Restart with durable record and independently supervised recovery | No old client/proof reuse; no forgotten fence, unverified rollback or optimistic success |
| SIGKILL during recovery/terminal commit | Recover the exact immutable phase without effect replay | At most one recovery write; ambiguity survives restart |
| Hotplug/seat/boot/owner/build replacement | New native and logind identities with independent DRM observation | Reject unsafe remap; distinguish unknown from restored |
| Power/lock/focus concurrently | Native S17 lock/input coverage, inhibitors and per-output presentation | No unlock, suspend or power handoff while restoration is unverified |
| Disk full, torn write, corrupt journal | Cold restart against real durable storage with injected faults | Fail closed, preserve evidence, never silently initialize new history |
| Native owner/compositor death | Real disposable KVM guest, not a synthetic mock | Fresh owner attestation; no client resurrection or forced UI confirmation |

**Evidence levels:** Component and synthetic-Wayland tests can establish
refusals and one-shot properties, but not actual compositor death, new GPU/DRM
scanout, correct native rule restoration or powered-output continuity. S21-2
requires exact-source Level A guest acceptance of real display effects and
recovery. The independent Level B interactive and Level C physical/Q11
requirements remain unchanged. Every qualification report must be source,
guest, provider, case and evidence digest bound; screenshots and successful
builds alone are not an oracle.

## Implementation acceptance and physical release

Source completion, Level A/B validation, implementation acceptance and Level C
release qualification are separate milestones. Missing maintained physical
hardware does not defer safely implementable source work or Level A/B testing.
It also cannot justify weakening their independent verification, recovery or
security requirements.

| Milestone | Completion requirement | Current boundary |
| --- | --- | --- |
| Source complete | Stages 3–5: separately authorized physical handoff, durable Root/Control completion, ordinary Keep/Revert/expiry release, committed adoption, authenticated successors and reference-aware bounded cleanup | Incomplete; public mutation remains prohibited |
| Level A/B validated | Exact-source real compositor display mutations and adversarial recovery in Level A, followed by applicable interactive Level B checks, retained case evidence and independent verification | Existing build/shell/S17 lanes do not complete the display-specific matrix |
| Implementation acceptance | Synchronized ADRs, qualification records and acceptance matrix; all applicable nonhardware gates and independent exact-head reviewer signoff | Pending source completion and Level A/B evidence |
| Level C release qualification | Maintained physical GPU/DRM scanout, multi-monitor/HiDPI, hotplug, protected input/accessibility, lock/power interactions and independent recovery/Q11 evidence | Outstanding; no maintained physical workstation is currently available |

After all nonhardware implementation gates pass, reviewers may assess merging
the implementation with the production effect disabled and Level C explicitly
outstanding. That assessment neither enables public mutations nor promotes
supported production operation. Activation requires the applicable physical and
other release gates. Until then retain the fail-closed public routes and the
existing unsupported production-operation status.

### Reserved preimages and independent protection

The current wire and transaction implementations preserve an original
in-process checkpoint, compensate under an independent native timer, and
reject old compositor topology from a different invocation in component
tests. A bounded bidirectional native-rule codec now reconstructs owned rule
fields exactly, and the protected receiver requires its canonical decode before
accepting a baseline digest. A separate root-only prepared observation carries
those validated preimages, native identities and prior overlays. The narrow
executor exclusively reserves and syncs an immutable private checkpoint before
native apply, then revalidates the original scope and clocks. Partial/corrupt
history, redelivery, unsafe paths or exhausted retention refuse dispatch. The
store also checks the complete bounded private envelope's dispatch against the
filename: a copied or renamed otherwise-valid checkpoint fences new reservations
and cannot allow redelivery under its former name. This is integrity validation
of historical comparison data, not replacement admission or restoration proof.
The existing private storage encoding is unchanged. The
records are historical data, not a recovery supervisor or authority journal;
by themselves they permit neither cleanup nor restoration. Those component tests do **not**
kill a compositor process or prove cross-compositor recovery. Independently
retained kernel observation now has a read-only mechanism: the executor subscribes
to kernel uevents before native sampling and retains the same socket and real
kernfs connector/device attribute descriptors. It matches the validated original
DRM tuples, bounds event draining, checks the global sequence watermark and
irreversibly refuses continuity after a gap, overflow, truncation, malformed
sender/data, DRM event, bound driver/bus ancestor event or attribute failure.
The independently supervised display protection process retains these witnesses
outside executor/compositor memory; continuation checks the original witness
before and after native handoff. Executor restart retains that separate process;
protection-service restart cannot reacquire its objects from saved identities. This is component-tested mechanism
code, **not accepted kernel/compositor-loss evidence**: real DRM hotplug, driver
unbind/reset, modeset behavior and kernel event delivery still require the exact
guest lane. It provides neither scanout/frame proof nor replacement admission.
Private startup fencing, authenticated one-use restoration and independent
restoration verification are implemented. Qualified terminal release/retention
cleanup and the complete native acceptance matrix remain required. The public Authority1 mutation methods remain unsupported.

Independent display protection also acquires the fixed `sleep:shutdown`/`block` inhibitor inside
the original prepared-checkpoint callback, before durable reservation or apply.
It retains this original logind FIFO beside the kernel witness, independently
of compositor/UI lifetimes. Current checks bind the exact root logind owner and
boot, reject sleep/shutdown preparation, and require the original CLOEXEC FIFO
to remain quiet and alive. Any failed transport, state, liveness or owner check
permanently poisons the lease; it is never reopened or reacquired. Kernel evidence
is rechecked after bus probes, and both protections surround native continuation.
The original kernel subscription also retains the successful and failed suspend
counters before native sampling. A cycle cannot be hidden by later logind
`PreparingForSleep=false`; either changed counter permanently fences continuity.
This does not survive protection-service death, bypass inhibitors, request power or supply
lock/frame/recovery authority. Terminal release and real startup/logind/
compositor-loss/power acceptance remain unfinished.
This contract cannot be marked complete until implementation, fault injection,
independent evidence and final security review exist on the same exact head.
