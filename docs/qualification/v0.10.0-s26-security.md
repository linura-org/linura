# v0.10 S26 adversarial qualification — portable data, revisions and nondelegable authority

**Status:** Proposed security contract; no new workstation Library application or physical native evidence qualified.
**Sources:** [ADR 0054](../adr/0054-s26-local-library-workstation-authority.md), [domain acceptance](v0.10.0-s26.md), [threat model](../threat-model.md).

## Security goal

A portable Setup/Profile, stale display revision, restored database, model-authored draft, impersonated actor or foreign-machine capability reference must never impersonate a current authenticated principal, supply reusable approval, grant the executor, select a weaker operation class/risk, delete a shared managed resource or claim machine convergence without independently verified native state.

| Threat / failure | Adversarial case | Required outcome |
| --- | --- | --- |
| Embedded authority | Imported bundle contains approval, executor material, policy/risk or secret values | Bounded parser rejects/does not materialize authority |
| Digest vs origin confusion | Integrity-correct bundle from untrusted author presented as authenticated/signed | Content integrity only; explicit provenance/consent, no trust upgrade |
| Identity substitution | Same Setup/Profile name or ID with different revision/digest | Exact ID/revision/closure/digest mismatch, no silent overwrite |
| Inconsistent references | Same logical intent at conflicting revisions across nested Setup | Reject or explicit incomplete graph, never guessed newest |
| Cycle/depth blowup | Nested Setups form cycles, huge/deep graph or huge bundle | Bounded traversal, no recursion/CPU/disk exhaustion |
| Stale CAS | Concurrent CLI and QML editor save from identical base revision | At most one accepted new revision, conflict for the other |
| Idempotency substitution | One request ID reused for different body or resumed in another authority epoch | Exact operation digest verification, no wrong semantic reuse |
| Import partial commit | Crash after some nested definitions but before transaction commit | SQLite atomic rollback or complete valid original transaction |
| Corrupt WAL/schema | Faulted transaction, oversized schema metadata, newer format/schema | Fail closed, no active DB loss or guessed migration |
| Backup restore rollback | Older valid DB replaces newer while service is active | Quiesce, safeguard prior state, no stale authority resurrection |
| Secret references | Missing secret ref, imported credential value or local secret leak in export | Report ref-only blocker; never export secret value |
| Machine-class mismatch | Profile from incompatible target or unsupported capability | Explicit blocked planning, no provider auto-fallback |
| Incorrect preview | UI `AdoptionReport.requires_plan` interpreted as approved plan | No executable effect; fresh canonical Control planning required |
| Client privilege laundering | Imported ActorId, shell, model or agent claims to be Principal | Trusted transport principal only, provenance separate |
| Current-state spoof | Old observation/provider/PlatformProfile gives false actionable diff | New target boot/session/provider/freshness and plan binding |
| Shared resource retirement | One Setup retired while another owns same resource | Retained shared or indeterminate; no cleanup without complete causal proof |
| Historical approval replay | Imported LifecycleRecord ApprovalReference or completed audit reused for apply | No grant or replay; fresh policy and managed prepare |
| Crash after effect | Native operation applied but reply/commit lost during multi-domain adoption | Indeterminate per-domain outcome, re-observe, never replay |
| False atomic machine result | Profile applies partially across network/storage/session providers | Per-effect verified progress and explicit partial/recovery state |
| Export path substitution | Symlink/hardlink/path traversal/wrong-owner artifact | Safe user descriptor, atomic publication and observed ownership |
| Restore file substitution | Backup URI changed after preview or live DB replaced unsafely | Exact backup digest/schema, writer quiescence and recovery |
| S17/S21 crossover | Foreign seat, lock, power/display transition invalidates review | Protected current principal/session and reauthorization |
| U/XSS data injection | Malicious Setup title/description renders HTML/QML or opens URL | Bounded escaped text, no shell/QML/markup execution |
| Evidence laundering | WIP fixtures or VM UI declared as supported physical machine adoption | Q10 and genuine Q11 remain independently required |

## Failure windows and evidence

Exercise before/after file open, canonical parser validation, duplicate conflict, SQLite transaction begin/write/commit, failure-injected WAL and fsync, local export temporary publication, backup validation and restore swap, fresh plan derived then provider changes, managed effect prepared before dispatch, native reply lost, independently verified result before commit and daemon restart. Reusing an old operation ID **only for the exact existing local idempotency semantics** is not a license to repeat machine effects or restore a historical plan.

Retain content digests, DB version, source SHA, causal ownership and masked error categories rather than raw secret refs/values, arbitrary imported labels, audit payloads, credentials or private paths in logs/model/qualification videos. A portable SHA-256 checksum is not an author signature. Historical approval references remain historical evidence, never current permissions.

**No complete causal proof = no destructive cleanup. No fresh current-machine plan = no effects. No quiescent verified restore = no live database replacement.** These deny-by-default boundaries cannot be relaxed to make a UI appear complete.
