## Required source-level tests

Implementation qualification must include focused tests for at least:

1. canonical proposal serialization is deterministic for semantically identical typed content;
2. supported proposal schema versions parse and unsupported-newer versions fail closed;
3. missing/unknown/duplicate/oversized fields are rejected before authoritative mutation;
4. executable shell text cannot substitute for typed capabilities;
5. model/provider output cannot assert approval, policy success or executor authority;
6. Linura Control constructs and minimizes semantic context before agent-runtime invocation, and secret canaries in raw Library/observation/retrieval/user data never reach runtime/provider input, proposal, diagnostics or audit;
7. deterministic mock provider produces replayable qualification fixtures;
8. provider timeout/cancellation/rate-limit/unavailability returns bounded non-authoritative failure;
9. malformed or truncated streaming output leaves authoritative intent unchanged;
10. prompt injection embedded in user/retrieved content cannot extend the capability registry or lower approval requirements;
11. stale observation revision is detected before proposal acceptance;
12. an observation that expires by time without a revision change is reacquired or causes acceptance to fail closed using trusted Control time;
13. stale policy/Library/capability-registry/existing-intent state is detected before acceptance;
14. capability references are resolved only against the current Control-owned registry;
15. acceptance decision identity/binding is exact-bound to principal + proposal ID/digest + accepted context + operation identity + create/revise action + exact target/revision expectation;
16. decision replay over changed proposal/context/operation/action/target material fails closed;
17. the authority-internal durable acceptance transaction/write-CAS guard is acquired before final authority/context/freshness/capability/decision revalidation;
18. every time-limited authority contributor is normalized to an exclusive first-invalid trusted-Control instant before aggregation; unit-conversion overflow, endpoint/successor overflow, unknown endpoint convention or inability to derive that instant fails closed rather than dropping the contributor;
19. the sealed acceptance-commit capability is transaction-scoped, exact-bound to the final Control validation and durable transaction, and carries both the final-revalidation trusted-time floor and the earliest normalized exclusive authority-validity deadline; write/CAS is permitted only when `time_floor <= now < deadline`, exact equality `now == deadline` is rejected, and loss of trusted-time monotonic continuity is rejected independently of numeric interval membership;
20. observation endpoint semantics are qualified explicitly: at the observation's own inclusive freshness endpoint it remains current when all other authority remains valid, while the first representable Control instant after that endpoint is its normalized exclusive deadline and write/CAS exactly at that normalized deadline must fail closed;
21. decision/approval endpoint semantics are qualified explicitly: for authority invalid when `now >= expires_at`, that `expires_at` instant is itself the normalized exclusive deadline and write/CAS exactly at it must fail closed while the immediately preceding representable valid instant may succeed when all other authority remains valid;
22. an injected database-lock, scheduler delay or internal-I/O stall after capability minting but before actual intent+acceptance-record write/CAS reaches or passes the sealed deadline because observation freshness expires, forces transaction rollback, and leaves both intent and acceptance-record state unchanged;
23. the same post-mint delay is exercised with observation freshness still valid but the exact-bound human/policy acceptance decision or approval reaching its normalized exclusive deadline before write/CAS, and the transaction must likewise roll back with no durable mutation;
24. a post-mint trusted-Control numeric clock rollback is injected after the sealed capability captures its authority-time floor but before actual write/CAS; even if the backward sample would satisfy `now < deadline`, `now < time_floor` must fail closed with no intent or acceptance-record mutation and must not revive expired observation or decision/approval authority;
25. a post-mint trusted-time source reset or rebind is injected while the replacement source returns a numeric value that still satisfies `time_floor <= now < deadline`; loss/change of the monotonic continuity identity must nevertheless fail closed with no durable mutation;
26. a post-mint condition in which Linura Control cannot establish whether trusted-time continuity is preserved is injected while the numeric sample otherwise lies within `time_floor <= now < deadline`; continuity-unknown must fail closed with no durable mutation rather than treating interval membership as sufficient;
27. the authority-internal Library acceptance primitive requires a sealed Control-minted commit capability that is not constructible/deserializable through public SDK/client/provider surfaces;
28. direct public `LocalLibrary`/SDK attempts to fabricate proposal acceptance are rejected and leave durable state unchanged;
29. accepted proposal is converted only to a normal `Intent` in `Proposed` state through the sealed authority-internal acceptance path;
30. a process failure before commit cannot reconstruct the transient sealed capability from durable/public identifiers and must re-enter Linura Control;
31. a lost response after successful commit followed by restart returns the same durable `IntentId`/revision and exact acceptance record rather than creating a duplicate;
32. proposal/operation/decision identity reuse with changed principal, digest, context, action, target or resulting-intent expectation fails closed;
33. proposal rejection/revision leaves no partial authoritative intent;
34. no-provider/manual operation remains complete without weakening trusted acceptance checks;
35. offline mode with a network-required adapter registered and explicitly selected rejects before adapter invocation or transport initialization; adapter callback/invocation and deterministic authentication/DNS/socket/transport counters remain exactly zero;
36. offline provider discovery independently encounters a registered network-required adapter without invoking its discovery/initialization callback or transport; all adapter/authentication/DNS/socket/transport counters remain exactly zero;
37. offline provider health checking independently considers a network-required adapter without invoking its health-check callback or initializing authentication/DNS/socket/transport state; all counters remain exactly zero;
38. offline fallback selection independently reaches a network-required fallback candidate after a local/no-provider path is unavailable and rejects that candidate before any adapter callback, authentication, DNS, socket or transport initialization; all counters remain exactly zero;
39. material assumptions and uncertainty are preserved for review;
40. if multiple advisors ship, disagreement and source provenance remain independently inspectable;
41. any later managed effect still routes through v0.6 authorization and independent verification;
42. provider-generated explanation/rationale never overrides deterministic validation;
43. public Library persistence APIs remain usable for their existing v0.7 non-acceptance purposes without becoming an alternate proposal-acceptance authority path;
44. Linura Control alone determines provider eligibility/discovery, selected adapter, cross-adapter schedule, aggregate deadline/budget, retry/fallback/advisor admission, caching/coalescing and aggregation policy;
45. a compromised/misbehaving runtime given one Control-admitted attempt cannot invoke an unselected second adapter, autonomously retry the selected adapter, activate fallback, initiate an additional advisor, or aggregate another provider result; every such attempt is rejected before the extra adapter callback/transport initialization;
46. an adapter given one Control-admitted attempt can initiate only that single provider invocation; after timeout, rate limit, transport failure or partial response it returns the bounded failure without internally retrying, reissuing or starting a replacement/resume request, and any repeated provider invocation without fresh Control admission is rejected before adapter callback or transport initialization;
47. aggregate Control deadline/budget state spans sequential provider attempts and cannot be reset, widened or re-based by runtime-local per-attempt state; a runtime attempt that asks for more budget/deadline than Control admitted is rejected/fails closed;
48. when multi-advisor support ships, Control—not the runtime—owns advisor scheduling and deterministic select/combine/reject aggregation, while per-advisor results remain separately attributed and inspectable.

## Dedicated v0.8 qualification

A dedicated v0.8 workflow must run the exact candidate with deterministic provider fixtures, adversarial inputs, concurrency races and failure injection. External hosted-provider availability must not be a hard dependency for reproducible release qualification; provider-specific smoke tests may supplement but not replace deterministic adapter conformance.

Machine-readable evidence should record at minimum:

- exact candidate SHA;
- proposal schema/version;
- provider adapter identifiers exercised;
- Control-owned provider-orchestration scenarios/results, including runtime self-selection/retry/fallback/advisor/aggregation rejection, adapter-internal repeat-invocation rejection and aggregate deadline/budget non-reset evidence;
- deterministic fixture digests;
- adversarial scenario names/results;
- Control-owned pre-runtime secret-minimization/canary results;
- stale-context and timer-only observation-expiry scenarios/results;
- normalized exclusive authority-validity deadline derivation, source endpoint convention/unit and aggregation results;
- sealed trusted-time floor and linearization-time numeric-rollback, reset/rebind and continuity-unknown results;
- exact-deadline observation-contributor boundary results;
- exact-deadline decision/approval-contributor boundary results;
- post-mint observation-freshness expiry at durable write/CAS linearization scenario/results;
- post-mint decision/approval-applicability expiry at durable write/CAS linearization scenario/results;
- post-mint authority-clock numeric rollback, time-source reset/rebind and continuity-unknown scenarios/results, each proving no stale authority revival;
- offline network-required adapter pre-invocation rejection results for explicit selection, discovery, health-check and fallback paths, including zero adapter invocation/authentication/DNS/socket/transport-init counters for each independent case;
- exact-bound acceptance-decision replay/substitution scenarios/results;
- final authority-serialization/concurrency scenarios/results;
- sealed Library direct-call rejection results;
- lost-response/restart idempotency and exact proposal/decision-to-intent lineage results;
- provider failure scenarios/results;
- explicit proof that no proposal restored or manufactured approval/executor authority;
- inherited v0.6/v0.7 qualification identities consumed by Trusted Release Proof.

- release-preparation and metadata-only authorization preserve the reviewed tree;
