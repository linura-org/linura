# S21-4 native removable-media implementation and acceptance

**Status:** S21-4 candidate safety modeling in progress; native effects unimplemented. **Profile:** `arch-hyprland-v1`.
**Parent contracts:** ADR 0045, ADR 0047, `contracts/v010-s21-design.toml`,
`docs/qualification/v0.10.0-s21.md`, and
`docs/qualification/v0.10.0-s21-security.md`.

This is an implementation checklist, **not an enabling operation registry,
native executor, security acceptance, evidence claim, or release promotion**.
All four S21-4 candidate effects remain disabled until independently qualified.

A bounded, pure Rust topology/preflight/postcondition model now exists in
`crates/linura-linux-observation/src/removable_storage.rs`. A separate read-only root-owned D-Bus ObjectManager adapter now collects
bounded drive/block/partition/filesystem and mount-state evidence with an
owner-consistency check and two matching native inventories. It now includes
seat, USB bus, and physical sibling correlations; resolves partition/table
ancestry; and rejects mounted, system, ignored, RAID and crypto-related siblings
in a non-authorizing drive-group safety review. Both native and higher-level
candidate preflights now deny physical removal when a sibling is mounted,
protected, missing block ancestry, or on a foreign seat. A read-only session-scoped
entrypoint now verifies kernel boot, active local logind user session, UID,
seat and logind owner before and after inventory, without granting Polkit
subject authority. Neither model nor adapter yet establishes exact
session/seat, physical device generations, busy/system media proofs, Polkit
calling subject, durable Control execution or independent post-effect
verification. A separate bounded kernel `/proc/self/mountinfo` parser now
checks the observed service's mount state for contradictions in the authority
process's mount namespace. Its matching result is only candidate evidence:
mount-namespace equality, device-instance identity, open-file/busy proof,
subject-bound permissions, and independently verified execution remain
mandatory. A separate dual-source candidate mount/unmount postcondition now
rejects changed owner/device lineage, foreign seat, collateral sibling changes
or disagreement between the UDisks2 state and kernel mount records. It is
not the durable Control verifier or a physical eject/power-off oracle. Native effects remain disabled and synthetic tests cannot
qualify hardware.

ADR 0047 defines the proposed operation-specific storage authority, authentic
native subject, physical and namespace identity, sibling protection, bounded
single-use execution and independently verified recovery. Its presence does
**not** enable any of the candidate methods.

## Operation boundary

| Candidate operation | Trusted risk floor | Native UDisks2 operation | Required independent postcondition |
| --- | --- | --- | --- |
| `operation:storage.filesystem.mount` | SecuritySensitive | `Filesystem.Mount` | Exact filesystem mount state and mountpoint(s), not merely the returned string |
| `operation:storage.filesystem.unmount` | Destructive | `Filesystem.Unmount` | Exact filesystem no longer mounted, with unchanged device lineage |
| `operation:storage.drive.eject` | Destructive | `Drive.Eject` | Independently observed physical-media ejection/removal where supported; no inference from `PowerOff` |
| `operation:storage.drive.power-off` | Destructive | `Drive.PowerOff` | Independently observed device power-off/removal where supported; no inference from `Eject` |

Each effect must pass the existing canonical Control **ManagedExternalEffect**
path, not a new authority plane. Provider-generated descriptors and client
risk/classification overrides are never accepted. These candidate IDs are
currently *design data*, not runtime registrations.

## Trust and topology evidence

1. Start with the authenticated calling principal, actual native logind
   session/seat, exact boot identity, and a fresh system-bus connection.
   Bind the real invoking Polkit subject; neither a client-supplied UID nor a
   root caller's `Can*` response can confer the user's authorization.
2. Acquire the UDisks2 unique D-Bus owner and revalidate it before each
   privileged handoff. Map the complete native `Drive`, `Block`,
   `Partition`, and `Filesystem` relationships with per-object identity,
   topology generation, kernel device identity, and all sibling volumes.
   Object paths, `/dev/sdX` names, labels, serials, and a claimed generation
   are insufficient *on their own* to establish unchanged hardware.
3. Reject duplicate or ambiguous device identity, partitions that cannot
   be conclusively tied to a single drive, provider loss or replacement,
   wrong seat/session, unexpected object-interface changes, and any
   incomplete sibling inventory. The selected resource must remain the same
   across planning, authorization, prepare, dispatch, and verification.
4. Forbid mutation of system/boot/root/swap devices, fixed disks outside
   explicitly qualified removable scope, busy/open filesystems, shared drives
   with mounted sibling filesystems, and unsupported native actions. Never
   infer safety merely from a caller-supplied `Removable` flag.

## Execution, loss, and recovery

- Preserve the existing durable pre-dispatch reservation, plan-bound human
  approval when required, audit, bounded timeout, and exact operation/resource
  identity. Dispatch only four narrow, separately reviewed native methods.
  Never expose unrestricted D-Bus calls, mount options, paths, `Force`,
  formatting, partitioning, arbitrary shell, or privilege fallback.
- Only native default/explicitly vetted UDisks2 mount behavior is eligible;
  prohibit caller-chosen mountpoints and arbitrary option dictionaries.
  Distinguish a busy/unmount denial from an empty device, a missing object,
  and a provider/subject authorization failure without leaking secrets.
- If the provider reply is lost, a timeout occurs, a device is unplugged,
  the bus owner changes, or the process restarts, preserve an **indeterminate**
  result. Reconcile by independent observation without redispatching mount,
  unmount, eject or power-off. A fresh user action requires fresh authority.
- A successful D-Bus reply is insufficient to commit. The verifier must be
  independent of the executor's success claim and must establish the exact
  postcondition. Lack of evidence remains indeterminate, never success.
- Physical ejection and power-down are distinct; disappearance alone may
  equally mean unplug, service failure or device replacement, so it is not
  positive proof of either action without separately qualified evidence.

## Implementation and acceptance gates

- [ ] Bounded read-only UDisks2 observer with exact owner, subject,
  session/seat, kernel identity, full ancestry, sibling set, and freshness.
- [ ] Typed Control operation descriptors and policy/risk review, no
  client/provider classification authority, no activation by docs alone.
- [ ] Narrow native executor with subject-bound Polkit, privilege isolation,
  strict arguments, durable attempt reservation and no blind replay.
- [ ] Independent native postcondition verifier, durable result state and
  observe-only recovery across restart, lost reply, hotplug and replacement.
- [ ] Adversarial tests for forged/cross-seat subject, owner substitution,
  device path reuse, incomplete topology, busy and system media, mounted
  siblings, malicious options, successful-reply-but-no-effect and failed audit.
- [ ] Exact-source Level A disposable Arch guest with **real UDisks2 and
  Polkit transactions** on disposable media, source/guest/runtime identities,
  negative outcomes and immutable evidence. A synthetic model is not this gate.
- [ ] Separately qualify real USB eject/power-off and multi-device cases on
  maintained hardware for Q11/Level C; an emulated/loop disk does not qualify
  physical USB behavior.
- [ ] All inherited canonical CI, Security, CodeQL, native S17 and applicable
  v0.10 gates pass on the final exact head, followed by independent review.

S21-6 owns graphical convergence; S21-7 owns cross-domain integration.
S17/S21 completion, `interactive_workstation.evidence_ready`, and release
support must not change in this PR without the separate protected evidence
process. Implementation can advance independently of S21-2 and S21-3, but
**acceptance cannot precede required dependencies and qualification**.

## Additional read-only kernel identity probe (inactive)

The independent `removable_storage_kernel_device` module now exposes a candidate
USB sibling-group witness using kernel `dev_t`, canonical `/sys/dev/block`
lineage, disk sequence counters, complete sysfs partition children, kernel
holders/slaves, root mounts and `/proc/swaps`. It rejects missing or changed
witnesses rather than constructing generations from UDisks2 hints. This probe
is **not** connected to a privileged dispatch and cannot authenticate the
actual Polkit subject. Host-level process open-file and mount-namespace proof,
transaction no-replay, real execution, and independent release acceptance
remain separate mandatory implementation and qualification gates.

The native `observe_scoped_kernel_drive` candidate path now joins two
read-only observations and rejects changed UDisks2/logind owners, seat, boot,
mount namespace or physical disk sequence, without permitting any mutation.

## Native PolicyKit subject review (non-authorizing)

The new read-only module verifies a kernel-credentialed system-bus sender UID
and PID against logind GetSessionByPID, active local seat and exact session.
It checks a root-owned PolicyKit daemon and uses the user's system-bus-name
subject for a non-interactive, explicit mount/eject/power-off policy query.
It repeats the caller/session and PolicyKit owner checks after the response.
No generic unmount action is invented: unmount requires its own verified
ownership authorization. This observational result cannot replace Control's
durable prepared authority, nor permit a privileged storage method.

## Actual caller mount namespace (candidate-only)

`removable_storage_namespace` now reads the *authenticated system-bus peer*
PID's bounded `/proc/<pid>/stat`, namespace inode and mountinfo. It compares
them with the authority process's mount namespace and mount view, checks
process start ticks and namespace stability before and after reading, and
rejects missing/recycled PIDs or mismatched mount states. The read-only
Polkit subject candidate requires two matching namespace witnesses; it
cannot approve any effect. This initial implementation deliberately denies
separate namespaces rather than guessing across them. It does **not** prove
system-wide open-file/busy-writer completeness, mount ownership, a protected
actual-user executor invocation or physical eject/power-off.

## Trusted Control candidate schemas (still inactive)

`linura-control::operation_registry` now validates all four fixed candidate
managed-effect descriptor bindings (provider, capability, resource namespace,
requested change key and minimum risk) at registry construction. Tests prove
their namespaces do not cross-match and **none of the four descriptors is
registered in the active seven-operation registry**. This preserves the
S21 contract's `register_runtime_operations = false` until the native
session worker, actual policy authority, durable dispatch and independent
post-effect verifier qualify. Mere descriptor construction grants no effect.

## Fresh candidate native mount/unmount review

The read-only `removable_storage_postcondition` path now performs another
scoped UDisks2/kernel read and verifies that the native owner, logind scope,
physical device insertion/diskseq group and all unrelated blocks remain
stable while the target mount state changes exactly as requested. Eject and
power-off explicitly return `NotApplicable`, not fabricated positive proof.
This remains candidate evidence, not an independent Control commit oracle:
actual user namespace/reference completeness, before/after chronology,
subject-preserving executor and the durable managed post-dispatch verifier
must be separately integrated and qualified.

## Strict sealed candidate effect encoding (inactive)

`linura-control::storage_contract` now has four distinct operation-specific
canonical `EffectDescriptor` encodings. Its resource suffix is exactly one
64-character lowercase nonzero digest, which is a **correlation token only**
until a trusted native observer attests its original subject, physical disk
instance, mount namespace and whole affected group. Method and desired state
are not caller-supplied free-form values; no mount paths, options, shell
commands, force flags or alternate methods can round-trip. Tests reject
cross-operation swaps, malformed generations, widened payloads and provider
substitution, and verify that the seven live registry entries remain unchanged.
A well-formed effect is still not a single-use dispatch permit or a claim
that a native storage mutation can execute safely.
