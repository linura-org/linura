# Reusable Level B qualification environment

Status: **Blocked — environment/operator not provisioned.** This is a setup and
handover procedure, not qualification evidence. The qualification-control host
is separate from the virtualization host and the disposable Arch/Hyprland guest.
Machine names, addresses, SSH identities and individual operator assignments stay
in private instance records outside Git.

Level B execution is optional under
`contracts/v010-workstation-acceptance.toml` and is deferred to S21-7 / S29
qualification work. Its unavailable environment does not block acceptance or
merge of a source-complete implementation slice with the complete real Level A
matrix and independent review. This document defines what a future Level B run
must prove; it does not make that run a prerequisite for PR #259. See
[ADR 0049](../adr/0049-implementation-and-deferred-workstation-qualification.md).

## Host and recovery requirements

Use an x86_64 Linux virtualization host that passes the repository VM and visual
readiness checks and exposes usable KVM to the qualification account. Check the
actual host; a remote Linux login, cloud console or CPU virtualization flag alone
does not establish usable guest acceleration. Hetzner Cloud currently does not
support nested virtualization ([provider FAQ](https://docs.hetzner.com/cloud/servers/faq/)).
A separate virtualization-capable host must be selected and verified before
provisioning the guest. Do not change the qualified resource profile to make an
unsuitable host pass.

Retain an authenticated SSH control route and a second recovery connection that
survives guest display loss. Keep the host management session independent of the
guest compositor. Use the existing loopback-only VNC and guest SSH forwarding;
remote operators connect through authenticated SSH forwarding. No public VNC,
guest password service, production credentials or shared administrator session
is required. Demonstrate recovery before destructive guest cases.

Prepare the host once through the repository's environment-creation workflow,
using its pinned tool versions. Task sessions run preflight and inventory rather
than installing mutable tools. Provision dedicated guarded build/image/evidence
storage according to [development workspaces](../development-workspaces.md).
On the virtualization host, run from the selected clean checkout:

```bash
bash scripts/preflight_codex_environment.sh
python3 tools/codex/doctor.py --profile vm
python3 tools/codex/doctor.py --profile visual
python3 tools/workstation_acceptance.py doctor --mode interactive --display vnc --record
```

A successful doctor report is readiness information, not a completed case or
source-bound acceptance result. Missing KVM, recorder, interactive access or
storage keeps the environment blocked.

The interactive doctor opens the actual KVM device and checks its API version;
the launcher explicitly requests KVM and keeps the reviewed four CPUs and
6144 MiB. QEMU must successfully initialize KVM. There is no TCG fallback for
this session, and passing these prerequisites does not establish S21 acceptance.

The physical Q11 protocol separately includes seven S21 cases: Keep, Revert,
expiry, hotplug, lock/power, compositor/Root replacement and shared-reference
retirement/cleanup. All require two identified physical outputs, completed S21
prerequisites and digest-bound physical execution provenance. The generic
display-scale capture remains required. The additional case inventory does not
execute those transitions or supply their independent postcondition oracle;
the S21 qualification runner and actual physical runs remain outstanding.

## Immutable per-source session

For each candidate, record the full PR source SHA and use an isolated clean
checkout. Obtain the sanitized prepared Arch substrate and its manifest through
the existing substrate contract. Verify it with the exact-source
`qualification/v010/shell-runtime/verify-substrate.py` before a private copy is
resized or booted. Keep the immutable base separate from every disposable guest.
Reusing host tooling and verified substrate bytes never reuses guest credentials,
reviews, native lifetimes, recovery grants or previous acceptance results.

The existing shell session launcher is:

```bash
bash qualification/v010/workstation-acceptance/launch-interactive.sh \
  --source-root "$QUALIFICATION_SOURCE_ROOT" \
  --prepared-image "$QUALIFICATION_PREPARED_IMAGE" \
  --prepared-manifest "$QUALIFICATION_PREPARED_MANIFEST" \
  --display vnc --vnc-display 1 --ssh-port 2224 --record \
  --evidence-dir "$QUALIFICATION_EVIDENCE_DIR" \
  --run-id "$QUALIFICATION_RUN_ID"
```

The variables identify private, verified instance paths; the storage identity
must also be configured as required by the existing launcher. It builds the
selected Git source archive, verifies the installed daemon digest, locks a
private evidence directory, starts a disposable guest and verifies requested
recordings. Operator SSH forwarding for VNC display 1 terminates at the
virtualization host's loopback port 5901. Keep the guest recovery forwarding
separate from the graphical connection.

Without additional arguments this supplies the existing shell session. To stage
the source-pinned native runtime, add `--s21-candidate` with the candidate directory
from the **same full source SHA**. Before the release build, the launcher verifies
its complete closed file inventory, source/recipe/contracts and all retained
digests using `tools/hyprland_display_candidate.py`. There is no reference-compositor
fallback for this mode. The guest receives root-private candidate and release
binary staging; each product binary is hashed after transfer. The same Level A
provisioner builds the native owner, verifies its compiled integration identity
and exact guest package inventory, installs the candidate and both exact-source
executors, and retains the product's secure-entry/capability installation rules.

Native mode runs Level A's genuine logind/S17 bootstrap check before starting the
interactive shell. Both Wayland and IPC sockets must have the kernel peer PID/UID
of that actual compositor. The loop retains its service invocation, PID and
executable inode; drift in those facts fails the session. Executing-image
inspection uses the disposable fixture's root read because the secure compositor
deliberately denies same-UID `/proc` inspection. Its nondumpability and native
peer-admission guards remain required. The additional retained
`native-session-bootstrap.json` claims **bootstrap only**. No password is enrolled
automatically and no operator identity or successful authentication is invented.

This wiring does **not** execute or qualify the S21 managed display mutation,
recovery or complete interactive case matrix. Its private runner, independent
case oracle and acceptance gate remain unfinished. A shell/S17 session, valid
candidate, recording or zero launcher exit status is not S21 acceptance.

## Operator handover and acceptance

Assign a named authenticated operator and a separate verifier before the run.
Record the host/guest identities, source SHA, substrate and compositor build
identities, dependency versions, resource profile, recovery access and run ID.
Use the [S21 exact-head matrix](v0.10.0-s21-display-recovery.md#exact-head-acceptance-matrix)
and its applicable inherited gates without enabling production Authority1 display
mutations. Exercise real native mutation, protected confirmation/denial, Keep,
Revert, expiry, lock continuity and compositor/Control/Root interruption and
recovery cases through the reviewed private qualification path. Require actual
postconditions and retained failure evidence, including ambiguous outcomes and
no-replay checks.

Retain bounded verified video plus per-case execution reports, independent
native/DRM/logind/Root observations, audit and durable lineage, binary/source
identities and artifact digests. The verifier checks the complete case inventory,
actual postconditions and evidence bindings independently. A successful recording
or launch is supporting material; neither establishes every case passed. Keep
credentials and protected input out of recordings, logs and exported evidence.

Level B remains blocked until the virtualization host, authenticated interactive
access, recovery path, operator, independent verifier and retained exact-source
case evidence are confirmed. A source edit invalidates acceptance for the new
head. VM evidence cannot promote maintained physical Level C/Q11 support.


## Required interactive cases and independent acceptance

When a Level B S21 qualification run is undertaken, acceptance requires the
complete interactive matrix below. The lane remains optional for implementation
acceptance; an optional launch does not make its evidence requirements optional
when claiming a Level B pass. Every family in the [exact-head matrix](v0.10.0-s21-display-recovery.md#exact-head-acceptance-matrix)
remains required, including its negative and interruption variants. The cases
below specialize that matrix for the authenticated human session; they do not
replace the automated Level A run or the physical Q11 matrix.

| Case | Actual interaction and independently verified result |
| --- | --- |
| B01 — unlocked Apply and Keep | The operator reviews the exact canonical layout and completes native administrator authentication. A separate protected Keep decision precedes the original deadline. Every enabled output has fresh completed presentation; the kept original intent, graph/provenance and matching ReleasedCurrent are verified. |
| B02 — locked Apply and Keep | Repeat with the actual S17 lock retained. Every affected output stays covered; no protected input or ordinary frame leaks into the locked session. Applying a layout cannot authorize unlock. |
| B03 — explicit Revert | The operator chooses protected Revert. The baseline layout, original native automatic rules/selectors and prior overlay ownership return. A numeric match alone cannot pass. |
| B04 — expiry and lost client | Independently exercise no decision, client death and lost replies. The original deadline is unchanged; restoration occurs at most once and unresolved outcomes remain indeterminate. Restart cannot recreate the old human decision or replay Apply. |
| B05 — denial and stale interaction | Exercise administrator denial/cancel, rejected or expired protected choice, missing authentication service and focus changes. No false completion or reusable approval may escape; the recovery route remains usable. Zero, one and multiple eligible administrator configurations retain their native bounded handling. |
| B06 — layout and visibility bounds | Exercise supported disable, mirror, scale and every supported transform, with a complete inventory of two to sixteen independently identified guest outputs. Reject last-visible-root loss, unsupported modes and stale/recycled output generations. Each successful layout must preserve a powered independent root and complete per-output evidence. |
| B07 — actual output replacement | Add/remove a real guest output before preparation and while the attempt is pending. Re-observe its native and kernel identities and S17 coverage. Connector names or a stable aggregate output count cannot establish continuity or safe remapping. |
| B08 — concurrent lock, input and power | Exercise lock/focus changes and the applicable managed power transition while display work is pending. Retained native protection and inhibitors prevent unsafe handoff; display approval cannot substitute for a separate S17 authorization. |
| B09 — process and journal boundaries | Interrupt the real compositor, owner, Control and Root at every applicable before/after-publication and spend boundary, including recovery and terminal completion. Cold restart must reconcile the exact phase without blind effect replay or reconstructed live authority. Retain failed/lost-ACK cases as well as successful recovery. |
| B10 — external recovery | Demonstrate the authenticated recovery connection before fault injection, then recover with the affected GUI unavailable. A forced UI confirmation, hidden session termination or unreviewed command cannot clear the case. |
| B11 — replacement-invocation kept intent | After compositor/Root replacement, explicitly map retained kept intent to the complete independently observed new inventory and baseline. Require a new canonical review, real protected authorization, durable prepare and actual new lifetime. Old recovery/adoption records supply only historical comparison. |
| B12 — shared references and cleanup | Demonstrate shared/in-flight/unknown ownership refusal, then independently completed new current lifetime before authorized old-reference retirement. Interrupt archive publication and bounded unlink. Preserve original preimages, spent state and semantic provenance; restart cannot recreate a grant or replay cleanup effects. |
| B13 — persistence and source faults | Inject real storage exhaustion, torn/corrupt/substituted history and mismatched binary/SDK/source identities in the disposable guest. Unknown state stays unavailable or indeterminate, evidence is retained, and no empty-history initialization or reference-compositor fallback can pass. |

The inventory is an acceptance requirement, not an executable runner or evidence.
B09/B12 require the complete phase/fault inventory of the final implemented
protocol, including its actual archival transitions. A missing implementation,
injection point, native oracle, operator action or retained variant leaves the
whole Level B result **Blocked**. No case may be omitted because it is difficult,
marked passed by a bootstrap, or substituted with a component fixture.

Before each case, the verifier records the exact source and candidate, installed
owner/executor binary digests, pinned dependencies, actual executing identities,
boot/seat/session generations, output inventory and applicable original clock
windows. The operator's authentication and decision use the product's protected
surfaces; credentials and protected response content are never evidence. Keep
private operator and verifier identities in the authenticated instance record,
with a stable reference from the retained run record rather than names in Git.

The independent verifier checks actual postconditions through separately acquired
native/DRM/logind/Root evidence and rechecks identity after the effect. It must
validate every case and variant against the exact source, complete ancestry and
original freshness/dispatch bounds. Producer booleans, executor acknowledgements,
Control receipts, matching geometry, video and an operator's assertion are
insufficient on their own. Supporting artifacts retain bounded bytes and digests;
missing, substituted, stale or contradictory evidence refuses acceptance.

Level B acceptance requires the complete Level A matrix and this complete interactive
matrix on the same source, a qualified resource profile and candidate, verified
operator/recovery access, independent verification, and retained evidence with no
support promotion. The present environment remains **Blocked — environment/operator
not provisioned**. The private S21 runner, independent case oracle and enforced
matrix admission still need implementation; this definition does not close those
source or execution work. Unrun B/C cases do not prevent the separate
implementation acceptance milestone and must not be reported as passed or used
to promote support. Level C/Q11 continues to require maintained physical hardware
in S30 independently of either VM result.
