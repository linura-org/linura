## Inherited S08 volume baseline

The existing `operation:audio.output.set-session-volume` is already a separately registered **transient** Control operation. Preserve its canonical 0–100% integer volume, exact `Audio/Sink` node ID + `object.serial` + `node.name`, audited same-UID session service `org.linura.Session1.SetAudioOutputVolume`, root-immutable embedded and sealed helper, no arbitrary process/command, durable bounded SQLite/WAL attempt reservation and strictly newer independently observed native postcondition. Neither this dossier nor an added candidate may replace or widen S08's trusted descriptor, helper or policy route.

The existing exact-source S08 shell-runtime qualification covers a controlled virtual PipeWire sink and specific normal/failure/restart cases. It remains **development evidence**, not the maintained physical Q11 or released workstation support. All old static/native qualifiers must continue to pass.

## Domain positive and negative acceptance

| Domain | Independent native acceptance | Required negative/failure proof |
| --- | --- | --- |
| Session identity | Authenticated same-UID PipeWire core/WirePlumber graph and selected logind session | Different UID/user bus, stale boot/session, provider owner/core replacement |
| Outputs | Bounded sink list, default alias, exact node/serial/name/media-class, hardware volume/mute | Node ID recycling, moved default, missing property, output removed mid-draft |
| Existing output volume | Same `Session1` descriptor, 0–100, fresh pre/post and durable audit | Failed sealed helper, altered file, stale snapshot, lost service, no fabricated receipt |
| Input/capture devices | Typed source/card/port, exact native identity, source gain/mute and capture stream state | Source/sink class confusion, false privacy status, source removal, session swap |
| Default input/output | Current actual provider metadata and verified resulting selected default | Moving default alias used as effect target, route not matching default |
| Stream routing | Exact stream/node/device/link/profile, verified actual native routing | Changed node serial, moved/removed stream, capture rerouted unexpectedly |
| Device profiles | Current supported card profile, activated ports and affected streams | Unsupported profile, half-applied route, lost input/output or unverified effect |
| Microphone privacy | Separate source mute, hardware switch where exposed, capturing streams/permission state | "Muted" shown as full capture prevention, foreign access or stale indicator |
| MPRIS inventory | User-bus unique player owner and bounded metadata/current track/position/status | Spoofed service, changed owner, hostile metadata/artwork/URI, missing player |
| MPRIS controls | Exact current player/track/allowed action and native postcondition; no shell | Wrong player, unsupported capability, auto-next race, lost reply, track changed |
| Interface convergence | Control Center, Quick Settings, OSD, CLI/SDK, keyboard, no-AI paths use exact Control request/receipt | QML direct PipeWire/DBus mutation, optimistic success, stale busy state, focus/a11y leak |
| Recovery | Restart of PipeWire/WirePlumber/linurad/player and independently reconstructed graph | Blind replay of managed route/profile, reused identity or stale notification |

Each new proposed operation is independently class/risk reviewed. Only later native proof may justify a **new** transient operation under the strict unprivileged/`UserState`/bounded-failure path. A microphone privacy claim or persisted routing effect with uncertain recovery must be managed or unsupported. For managed effects exercise full request/observe/plan/validate/authorize/prepare/execute/independently verify/commit/audit/reconcile including success/no-change/denial/stale/timeout/restart/lost reply/audit full/corrupt store.

MPRIS Next/Previous may advance automatically or report a different track and therefore require a reviewed postcondition strategy that does not treat unchanged `mpris:trackid` as guaranteed evidence of no action. A method reply establishes at most dispatch; post-effect proof must reflect the claimed result and the native limitations. Do not present a new media effect as "verified" where a correct postcondition is not independently observable.

## Qualification levels and evidence binding

**A — automated exact-source Arch/Hyprland VM:** Actual user PipeWire/WirePlumber, controlled virtual sinks/sources/streams, native MPRIS test player, real session-bus/Control protocol and independent observations. Capture source SHA, helper bytes/manifest hash, provider graph/node/object-serial generation, UID/session/boot, observed effect pre/post and diagnostic failure cases. Pure mock components are not native support proof.

**B — interactive VM:** Same pinned source and substrate; manual playback controls, protected microphone UX, keyboard/pointer/semantic accessibility, focus/reduced motion/HiDPI, OSD and no-AI GUI/CLI state convergence.

**C — maintained physical workstation/Q11:** Actual speaker/headset/microphone/card/profile, physical mute and permissions **where claimed**, independent real capture-state and hardware evidence, hotplug, Bluetooth audio integration where supported, native failure/recovery and shared Q11 source/boot/seat/visual/a11y binding. Virtual sinks, video or synthetic tests cannot substitute for real hardware and privacy assertions.
