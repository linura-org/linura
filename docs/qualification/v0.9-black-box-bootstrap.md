# v0.9 black-box production bootstrap qualification

## Purpose

The v0.9 QualificationEnvironment must qualify the release-facing production entry point rather than reproduce production security transitions inside the qualification harness.

The canonical deferred-owner proof is therefore:

1. create a fresh supported Ubuntu 24.04 / amd64 / QEMU-TCG guest and an explicitly hostile `linura-preparer` authority fixture;
2. establish the bounded Q8 prerequisites and isolate qualification-only transport from the product SSH observation surface;
3. invoke the exact-source production `linura-firstboot --bootstrap <absolute-state-root>` entry point as root from an out-of-band qualification observer;
4. let production own preparer process termination, supplementary-group removal, password locking, SSH removal, sudo revocation, authenticated revocation receipt creation, and owner-handoff state transition;
5. independently observe the resulting operating-system authority state without reproducing the mutation algorithm;
6. power-cycle the same persistent guest and invoke the same production entry point again;
7. require the restarted invocation to re-observe the authority boundary and converge without replaying historical authority.

## Separation of responsibilities

The qualification harness MAY create hostile initial conditions, control QEMU power cycles, isolate its own transport, launch production, and observe externally visible postconditions.

The qualification harness MUST NOT revoke `linura-preparer`, mint production revocation receipts, mutate production owner-handoff state, or substitute qualification-only transition binaries for the release-facing proof.

Qualification-only transition binaries remain permitted for fault-injection coverage of prepared/effect-started crash and reconciliation boundaries. That adversarial coverage is supplemental; it cannot stand in for the canonical production-entry proof.

## Authority observations

The independent postcondition requires all of the following after production convergence:

- no process executing as `linura-preparer`;
- no supplementary-group membership for `linura-preparer`;
- the preparer password is locked;
- preparer SSH authorization is absent;
- no effective sudo command remains available to the preparer after complete sudoers policy evaluation;
- `/etc/sudoers` remains valid;
- production emits `owner_enrollment=owner-enrollment-pending` and `preparer_authority_inherited=false`;
- the authenticated production revocation receipt exists inside the protected production state root.

The verifier observes these facts independently. It does not implement the revocation operation.

## Release evidence

Trusted Release Proof must bind evidence from the fresh-state production-bootstrap scenario, including exact source SHA, pinned base image digest, qualification environment identity, transcript digest, first successful production invocation, persistent QEMU power cycle, restarted production invocation, and independent authority postcondition.

A failure of this proof is a release blocker. Re-running an unchanged failing head is not remediation.
