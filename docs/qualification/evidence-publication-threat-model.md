# Private R2 evidence publication — security threat model

- **Status:** reviewed design for the controlled Level A publisher; live R2 deployment is not qualified by this document
- **Decisions:** [ADR 0034](../adr/0034-private-qualification-evidence-publication.md), [ADR 0035](../adr/0035-isolate-media-admission-from-r2-credentials.md)
- **Contract:** `contracts/evidence-publication.toml`
- **Implementation:** `tools/evidence_publication.py` and `.github/workflows/publish-qualification-evidence.yml`

## Assets, scope and authority

Assets are the private qualification files (including screen recordings), the source/run/case provenance, selection reason and environment-review attribution, the publication index, and the restricted R2 credentials. The archive supports historical diagnostics; neither its recordings nor its index establishes test success, a physical workstation qualification, a release-support claim, or any Linura runtime execution authority.

The enabled surface admits **selected passing Level A** exact-main-source `workflow_dispatch` bundles into private `baselines/` (180 days) or `regressions/` (90 days). Level B, Level C, releases, raw diagnostics and failed runs have **no publication authority** through this workflow. Their future intake needs a separate threat model, retention decision and reviewed implementation. R2 bucket privacy, lifecycle, GitHub environment protection and the first live upload are external operational prerequisites, not claims established by PR tests.

## Trust boundaries and trusted computing base

1. **Qualified run to downloaded artifact — untrusted bytes.** The selected run/attempt comes from authenticated GitHub Actions REST, not a file in the artifact. Successful status, exact source SHA, protected `main` branch, exact approved Level A workflow and `workflow_dispatch` are required. The artifact name includes the attempt; the manifest separately binds run, attempt, source, contract, complete case results and the recording.
2. **Artifact to credential-free admission job — independently checked admission.** Manifest and sidecar digests, exact required runtime cases and the retained `cases.tsv`, artifact paths/sizes/digests, recording metadata, FFV1/Matroska video structure and no audio are verified before publication. Files must be regular, single-link, safe-name files; publisher staging reopens them without following symlinks and rehashes a private immutable-for-this-run snapshot before uploading. File bindings authenticate bytes against the trusted source run only when the protected producer and GitHub provenance are trusted; a checksum alone is not a signature.
3. **Admission transport — separate runner and digest-bound receipt.** The credential-free job snapshots only verified files, generates a canonical admission receipt and transmits both through a one-day workflow artifact. A trusted GitHub job output carries the receipt digest independently. The protected job rechecks source, job, selection, policy, complete file inventory and file digests, and performs a second O_NOFOLLOW snapshot. It does not execute any code or media parser from the transferred artifact. A decoder compromise cannot directly read R2 secrets, although it could compromise the admission job and its narrow GitHub token.
4. **Human selection to protected environment — separate authorization.** An operator explicitly selects source/run/attempt/category and reason. The `qualification-archive` environment requires a configured reviewer and main-only deployment. GitHub's run-wide approval history is not attempt-specific: publication-job reruns are refused at preflight and in admission; retries require a **new manual dispatch and fresh environment approval**. The index retains both selector and reviewer, publication run/attempt and exact publisher-code SHA. GitHub retains the primary approval event; the index is a corroborating record, not a substitute.
5. **Approved workflow to R2 credentials — restricted effect.** Credentials are injected only into the upload step of the protected GitHub-hosted archive job. They are absent from the media-admission job and ordinary PR/qualification workflows and excluded from artifact/metadata/log payloads. The publisher checks the configured private bucket name and exact Cloudflare HTTPS account endpoint and uses bounded S3 operations. Admission relies on the credential-free `ffprobe`/FFmpeg, pinned actions, GitHub job/artifact/output integrity and its runner. Archive relies on a different trusted runner, `gh`, Python and AWS CLI, without a media decoder. These external tools and runner components are part of the trusted computing base, not cryptographically fixed by the artifact digest.
6. **R2 objects to index/readers — commit is not authenticity.** Object names bind category/source/run/attempt. Writes use `If-None-Match: *` and each object is read back and checked for expected length and SHA-256. A private SHA-addressed index is written **last**; an absent index means incomplete publication. An index is an inventory/commit marker, not an access token, immutable WORM guarantee, or independent signature. Any later viewer must authenticate the requester, verify referenced object bytes and detect expired, missing or altered objects before displaying evidence.

## Attacker capabilities, controls and residual risks

| Threat / attacker capability | Current controls and detection | Residual risk / required response |
| --- | --- | --- |
| Malicious or substituted run artifact; forged manifest/cases; modified recording or sidecars | GitHub-backed run/attempt/branch/workflow success, complete canonical case verification, manifest and per-file digest/size bindings, media probe, no-follow private snapshot | A malicious actor who can compromise protected `main` or its producer can manufacture apparently valid evidence. Protect source/workflow changes with reviewed main-branch gates. Suspend publication if producer integrity is uncertain |
| Artifact path traversal, symlink/hardlink replacement, file races, oversized or malformed video | Bounded names/file count/total size, one-link regular-file requirements, O_NOFOLLOW snapshot, stable inode/metadata and rehash, bounded `ffprobe` execution | Decoder bugs or runner resource exhaustion are not eliminated by time/size limits. Keep media tools patched, isolate the GitHub-hosted job and treat validation faults as denial, never success |
| Selector impersonation; stale approval; approval configuration relaxed; unsafe workflow requesting the environment | GitHub actor/workflow identity checks, protected main checkout, recorded `qualification-archive` environment approval, attempt-1-only publication and fresh dispatch on retry | GitHub environment settings are maintained outside this repository. A compromised GitHub administrator, reviewer or protected workflow can bypass procedural controls. Independently inspect environment rules and restrict which workflows can access credentials via protected source and review |
| Leaked R2 token or compromised credential-bearing runner/step | Private bucket-scoped token, no public R2 endpoint, credential exposure only in upload step, no secret-bearing output, rotation and monitoring | R2 Object Read & Write tokens can potentially read, overwrite or **delete** private objects. `If-None-Match` is a behavior of this publisher, not a storage-enforced no-delete/no-overwrite policy. Revoke/rotate on suspicion, investigate R2 logs and reconcile against independent GitHub evidence. Storage-enforced immutability requires a separately reviewed restricted broker or suitable finer-grained controls |
| Tampered/removed index, partial write, failed readback, publication retry, lifecycle expiry | Exact readback before indexing, conditional index write, stable-field comparison and full original approval-provenance validation on retry, retained first approval metadata, separately configured prefix lifecycle | A privileged R2 actor can alter or remove both objects and index; an index can outlive its contents. Reconcile index and referenced bytes, report unavailable/corrupt evidence, do not infer a valid pass from archive state. Investigate orphaned objects; delete only through separate administrator approval |
| Accidental disclosure via video, bound diagnostics, public URLs or long retention | Level A-only admission, required manual selection and protected review, private R2 bucket, deny B/C/release categories, unbound diagnostics excluded, 180/90-day lifecycle policy | Checksums and media metadata **do not detect secrets or PII in pixels or logs**. The operator/reviewer must inspect sensitivity and sanitize or decline each candidate. Do not enable `r2.dev`, public custom domains or automatic public replay. Periodically verify actual lifecycle and access settings; follow documented privacy-deletion/tombstone process |
| Untrusted data reaches privileged operations or is misread as qualification authority | Explicit command allowlist in publisher (verified `put-object`, `head-object`, `get-object`), fixed private destination, no arbitrary command arguments from manifest, independent qualification status | Publication itself conveys no Linura policy/executor permission. Other consumers must never turn an index, digest, object URL, GitHub status or video into a runtime authorization or release promotion |

## Recovery, monitoring and activation checks

An interrupted upload without an index is incomplete; a fresh approved dispatch may verify and reuse exactly matching bytes. A completed index is never silently overwritten. Suspected compromise requires suspending publication and archive access, rotating credentials, preserving independent GitHub run/review provenance, checking remote object hashes and recording authorized deletion/tombstones. Do not automatically delete on a failed run; failed partial uploads need explicit administrative reconciliation.

Before enabling production publication, an operator must independently verify the private R2 bucket and absence of public access, the correct account/jurisdiction endpoint, bucket-scoped secrets, `qualification-archive` main-only deployment and reviewer enforcement without administrator bypass, object-lifecycle policies and a successful **approved** exact-main-source upload with readback. Recheck after configuration or credential changes. These external checks and real-media/live-R2 qualification cannot be replaced by the mock integration tests in this PR.

Changes to the approval, credential exposure, trusted source, index format, privacy category, retention or remote access boundary require an updated threat model and a reviewed architectural decision.
