**State:** implementation/qualification pending
**Claim class:** Experimental

This document is the release qualification contract for v0.7.0. It must be completed with exact-source reproducible evidence before release authorization. A checked item requires executable repository evidence and, where applicable, dedicated disposable-system evidence; prose alone is not qualification.

## Required source-level tests

The implementation must include focused tests for at least:

1. intent creation with multiple requirement kinds;
2. legal activation, suspension/reactivation, supersession and retirement;
3. illegal terminal-state transition rejection;
4. stale expected revision rejection;
5. exact operation-id retry and substitution rejection;
6. process reopen preserving current projections and append-only history;
7. one resource shared by two active intents remains owned when one retires;
8. one resource owned only by a retiring intent is reported cleanup-eligible;
9. incomplete causal ownership is not cleanup-eligible;
10. Setup revision monotonicity and immutable prior revisions;
11. nested Setup cycle rejection;
12. MachineProfile machine-class preservation;
13. deterministic export bytes for identical content;
14. export/import round trip on an empty second store;
15. digest tampering, malformed escapes/records and unsupported newer format rejection;
16. import collision behavior is deterministic and non-partial;
17. adoption dry-run does not mutate the target store;
18. missing secret references are surfaced without reading/storing secret values;
19. machine-class mismatch is surfaced before adoption;
20. backup/restore preserves all Library records and histories;
21. corrupt/newer-schema restore source is rejected while the active database remains valid;
22. transaction rollback prevents partial current/history state.

## Dedicated v0.7 qualification

A dedicated workflow must execute the exact candidate against fresh temporary local stores and exercise restart/failure boundaries. Where behavior depends only on SQLite/filesystem durability rather than Linux privileged mutation, deterministic host qualification is preferred over inventing a VM dependency. Any test that crosses the existing v0.6 managed systemd effect must continue to use the previously qualified disposable-system boundary.

The dedicated qualification must archive a machine-readable evidence artifact containing at minimum:

- candidate commit SHA;
- Rust/toolchain identity;
- schema version;
- portable-format version;
- test scenario names and terminal results;
- database integrity-check result after restart/recovery scenarios;
- digest of the exported portable round-trip fixture;
- explicit statement that no imported artifact restored approval/executor authority.

## Release proof integration

Trusted Release Proof for v0.7.0 must fail closed unless:

- canonical CI, Security and CodeQL succeeded for the exact release source;
- dedicated v0.7 qualification succeeded for the exact release source;
- inherited mandatory v0.4/v0.5/v0.6 durability/executor/lifecycle qualifications required by the release machinery remain successful;
- candidate artifacts reproduce and match declared digests;
- metadata-only release authorization preserves the reviewed implementation tree.

## Terminal publication evidence

Publication evidence remains intentionally absent until tag-last immutable publication and independent release verification complete. Post-release closure must then create/update the terminal publication record and advance the roadmap from v0.6.0 -> v0.7.0 only after independent verification succeeds.
