# v0.10 S21 security qualification — workstation device effects

**Status:** Proposed adversarial acceptance; no native/security evidence claimed.
**Architecture:** [ADR 0045](../adr/0045-s21-workstation-device-authority.md); [system threat model](../threat-model.md).

## Security objective

A display, brightness, removable-media or power request must not change actor, policy, resource, scope or operation class after authorization; bypass S17 lock coverage; use ambient privileged execution; cause silent storage loss; replay ambiguous effects; or misrepresent a failed verification as success.

## Adversarial matrix

| Threat | Required negative case | Independent proof |
| --- | --- | --- |
| Caller/provider downgrade | QML, CLI, agent, config and provider supply weaker effect class, risk, target or approval | Trusted registry and policy reject before executor handoff |
| Object identity replacement | Recycled connector, block path, D-Bus owner, media ID, old boot/session/seat or provider generation | Fresh native peer/owner/object re-attestation denies substitution |
| Lock-output race | Hotplug or remove output while locked, compositor/security-owner restart, unknown lock coverage | Native `ext-session-lock` generation/coverage assertions on every active output |
| Display blackout | Unsupported mode, hidden primary, last local output removed, failed rollback, lost compositor acknowledgement | Independent topology and last-known-good recovery, not a QML prompt |
| Backlight authority | Wrong session/device, changed bounds, mock backlight, unqualified privileged sysfs access | Kernel/logind owner/bounds/read-after-write and explicit unsupported state |
| UDisks2 privilege escalation | Untrusted mount path/options, wrong Polkit subject, foreign UID, ambient root permission | Native constrained UDisks2 call arguments and subject-bound Polkit denial |
| Media loss | Eject with busy/mounted siblings, multi-LUN alias, service loss, unplug mid-effect | Drive/volume topology, busy-denial, no-force, distinct Drive.Eject/Drive.PowerOff postconditions and independent state evidence |
| Lost-reply replay | Device/compositor/power effect applied but reply missing; restart or UI retry | Durable indeterminate record and observe-only reconciliation without redelivery |
| Power unsafe dispatch | Late `block-weak` inhibitor, other session, lost secure coverage, unauthorized idle action | Existing S17 native safety review and typed effect parity |
| UI authority illusion | Forged success, stale snapshot, screen-reader/focus/pointer interception, leaked secrets | Exact receipt plus independent observation, a11y/input and secret-safe diagnostics |

## Fault and recovery requirements

Exercise process/bus-owner replacement, provider timeout, shell crash, power loss, hot unplug, compositor restart, seat switch, missing audit persistence and partial state effects. Each case must reject stale approvals, not accidentally replay an irreversible effect and retain explicit indeterminate outcomes until independently classified. Do not weaken S17 secure lock, delay inhibitors, authenticated principal, no-force or native break-glass recovery.

## Keep authorization regression cases

Exercise original administrator-approval revocation/expiry, changed policy or
source risk revision under an unchanged registered floor, changed principal,
material/provenance/evidence substitution and Control restart between apply and
Keep. The already-applied layout must never replace the original ChangeProposed
review with NoChange. Current registration/policy/approval checks surround the
protected interaction and durable decision I/O; no rejected decision can replay.
A lost process-local review must deny Keep while read-only reconciliation can
independently recognize timer restoration without another apply. These component
cases do not establish native protected interaction or compositor-death recovery.

## Evidentiary boundary

The production continuation transport must reject ordinary/root bus callers even
when they know correctly shaped transaction, effect and decision hashes. Test
both Keep and Revert, zero/malformed hashes, substituted material/correlation,
changed owner/connection and deadline equality. The original native dispatch's
wall and BOOTTIME clocks must reject clock rollback and suspend-inclusive expiry;
observing a terminal phase cannot revive a consumed decision. Successful explicit
Revert, duplicate/reflected decisions, expired choices and independent timeout
restoration are component regressions. Actual protected-input/native composition
and cross-compositor recovery remain required; these fixtures cannot qualify them.

The current deterministic fixtures cover complete journal-chain validation
before continuations, native-attempt digest substitution, historical checkpoint
binding/generation/principal substitution, truncation and bounded decoding. Generic
read-only monitor facts and partially applied owned targets cannot qualify a new
mutation checkpoint. Actual pinned native rule tests cover automatic placement,
custom timing, identity drift and preservation of unrelated rule properties. These
pure rule/wire tests do not establish continuity across compositor replacement.
Shared Rust/C++ baseline-guard vectors cover native and Linura-owned rules,
disabled ownership, sorted output records and changed rule/identity/target data.
The original checkpoint guard must reach root's strict fresh projection and the
owner's last native snapshot; recomputing a replacement expected guard at dispatch
would hide drift. A matching digest cannot stand in for native geometry,
authenticated peers, policy, managed prepare or independent post-effect proof.
The deterministic restoration fixture deliberately reports satisfied geometry
while its canonical native rule digest changes; final Control retirement must
reject it without another apply. Desired-layout verification also requires
complete native overlay ownership rather than a coincidentally matching layout.
The matrix also covers every pre-effect journal write failure (including native
baseline capture), decision write failure, lost apply/decision replies and SQLite
restart without replay. Restoration retirement uses the existing blocked
authority state; the separate restored phase cannot claim desired-state commit.
The retirement/terminal-journal crash gap must finish by fresh baseline evidence
without another effect. Native gate/timer fixtures exercise deadline equality,
suspend-inclusive expiry, clock failure, exact generations and coverage,
one-use restoration, acknowledgement ambiguity and teardown. They do not prove
recovery after native-owner process death, integration with S17 transitions or
the behavior of a real pinned compositor. Those remain activation blockers.

The durable admission fixtures additionally reopen SQLite, lose native attempt
availability, substitute a new compositor invocation and attempt another request
on the same seat. No new apply is admitted until the original work is independently
retired. A native Confirmed flag without retained protected Keep, and a Restored
flag with the wrong independently observed layout, cannot settle recovery.
Explicit status and one on-demand read-only reconciliation both retire proven
restoration before separate new authorization. Bounded namespace queries cover
literal prefix matching, overflow, reopen and tampered unselected rows. These
checks establish Control fencing, historical ownership capture and bookkeeping,
not restoration in a replacement compositor or resumption of native automatic rules.

Component fixtures cannot prove real compositor locked-output coverage, physical backlight safety, USB power/eject or Q11. Level A exact-source native tests, separately corroborated postconditions and Level C hardware evidence are mandatory when their support claim requires them. Security evidence cannot be promoted by ADR adoption, new contract text, video alone or an optimistic client receipt.

## Protected scanout storage and scope retirement

The pinned compositor build additionally runs real GLES framebuffer readback on
its software renderer. Larger and rotated storage must be opaque across every
pixel despite an old viewport, partial scissor and restrictive channel masks.
An incomplete framebuffer must fail. This is rendered-storage evidence, not a
hardware presentation, protected-input or end-to-end display mutation result.

The native adapter must not initialize client buffers or overwrite a buffer
already pinned for scanout. Placeholder initialization requires the compositor's
current owned write, a live consumed Apply scene, bounded scanout storage and
fresh protection/power checks after rendering. The original complete-inventory
check remains enforced; the initialization path does not admit an unrelated
modeset or finish the still-required transaction-bound mutation handoff.

Separate frame regressions cover buffer substitution, stale configure/result/
presentation, failed queued submission, missing hardware completion, commit-ID
reuse/wrap and opaque-frame substitution for owner content. A black frame revokes
the prior Ready input epoch before submission. Only a separately submitted and
hardware-completed owner-content frame can make interaction eligible again.
An already consumed scope never rearms. Scope history rejects all live replay
and capacity eviction; reclamation requires both original deadlines to expire,
and retained clock floors reject rollback after reclamation. BOOTTIME expiry
alone must not allow the same digest to acquire a second mapped deadline.

The private native protocol transports both original absolute deadlines. Wire
fixtures exercise all 64 BOOTTIME bits and reject a missing bound before creating
a scene. The real owner/client-server fixture supplies a shorter original boot
budget than its wall budget and verifies that the recipient preserves the gap.
Native interaction fixtures check deadline equality, delayed admission, stale
consumption, substituted boot deadlines and overlong windows. Scope history keeps
the original boot deadline, without deriving a replacement from wall time.
