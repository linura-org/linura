# v0.10 S26 qualification — Local Library, Setups and MachineProfiles

**Status:** Proposed extension acceptance; v0.7 released storage qualifications remain authoritative and are not requalified by a new UI.
**Target:** `arch-hyprland-v1`; predecessor S16; S27 downstream.
**Contracts:** [ADR 0054](../adr/0054-s26-local-library-workstation-authority.md), [inert design](../../contracts/v010-s26-design.toml), [adversarial security](v0.10.0-s26-security.md).

## Baseline and evidence ownership

The released `LocalLibrary` already owns durable intent, immutable Setup/Profile revisions and causal owner state. Phase S26 must run (not replace) the v0.7 qualification and test effective GUI/CLI/SDK integration against **that same store**. Bind source SHA, Library file identity/schema, WAL/transaction and relevant SQLite version, exact root+closure IDs/revisions/digests, authenticated principal, target machine and capability/PlatformProfile context, imported bundle digest, original operation-id semantics and fresh post-operation readback. An SQLite commit is proof of local state only; actual machine state requires separate Control plan and independent native observations.

The first-party workstation must represent *selected Library revision*, *persisted/reused local revision*, *fresh reviewed target plan* and *actual independently verified machine postcondition* as four distinct states. An `AdoptionReport` or import digest is **not** an executable `ReconciliationPlan`. If a required domain/credential/provider is unsupported, the plan cannot be executed; leaving the local Setup installed is not “machine applied.”

## Classification and failure gates

Four disabled proposed operations are `LinuraOwnedState` wrappers around existing local storage semantics (Setup/Profile save/import). Four disabled proposed operations are conservative `ManagedExternalEffect` for separately selected export and backup files, including destructive restore; review user-scoped filesystem class independently before enabling. No new generic workstation apply operation exists. The existing v0.7 local-library storage methods are **not deactivated** by these proposals. Future native domain effects use their own registered Control operations and complete managed/transient lifecycles.

For local writes: authenticated owner, exact base revision and operation ID, atomic transaction, foreign-key/integrity check, idempotent same-request handling and independent readback. For managed external file effects: trusted plan/policy/prepare, safe descriptor-based user destination, independent artifact verification, durable ambiguous recovery and no blind replay. For actual machine adoption: per-native-effect authority and independent final state with original causal plan/owner identity. Test success, no-change, stale, denial, cancellation, crash before/after commit, interrupted export, restore failure and fallback.

## Qualification levels and inherited gates

**A — exact-source local + Arch VM:** Retain released real SQLite v0.7 crash/WAL/schema/bundle tests, run native process reopen/import/export and signed-off exact-source GUI/CLI integration and representative actual Control/registered domain plan verification. Pure mock adapters cannot qualify real native effects.

**B — interactive Hyprland VM:** Actual QML `org.linura.UI 1.0` Library/Setups/MachineProfiles, nested graph/owner disclosure, exact revision compare, import review, no-model path, keyboard/pointer/screen reader, focus/reduced motion/HiDPI, error/restart handling. Recorded video supports visual review but does not prove SQLite or native machine mutation.

**C — maintained physical workstation/Q11:** Real installed machine and selected supported Setup/Profile, actual session/seat/boot/capability/credential identities and independently verified underlying system effects, physical interaction/accessibility, interruption/restart/ownership retention; never infer Q11 from a successful local import or virtual guest.

Keep v0.7 released durable qualification, v0.8 proposal and v0.9 migration/first-boot/recovery, S17 session, S21 device/power, v0.10 Q9–Q14, visual/baseline, CodeQL, Security and exact-head canonical checks. Candidate architecture and test sources cannot mark S26 complete or set `interactive_workstation.evidence_ready`.
