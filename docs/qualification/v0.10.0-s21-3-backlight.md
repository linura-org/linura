# S21-3 native backlight: implementation and qualification ledger

Status: **implementation in progress; writes disabled; not release qualified**.
Scope: v0.10 / S21-3 / arch-hyprland-v1. Governing decisions:
ADR 0045, [ADR 0046](../adr/0046-authenticated-user-session-execution.md),
and contracts/v010-s21-design.toml. Neither this ledger nor
passing unrelated regression checks activates a brightness operation.

## Exact contract

- Proposed trusted operation: operation:display.backlight.set-brightness
- Native provider: logind-backlight; observation: display.backlight.observe;
  class: ManagedExternalEffect; risk floor: SecuritySensitive;
  material change key: native_value.
- Canonical proposed resource: `backlight:physical:<boot>:<uid>:<session>:<created-us>:<device-generation-uuid>`.
  Material seat, provider invocation, panel mapping, bounds and qualification
  revision must also remain bound by fresh canonical observation/plan evidence.
- Native effect method after all authorizations: logind Session.SetBrightness
  on the exact, uniquely owned session; no generic D-Bus forwarding.
- Present state: **not registered, not executable**. Nothing here
  weakens the existing S17 operation registry or protection gates.

## Landed isolated read-only parts

The backlight observation module has strict, fail-closed integer
conversion, sample validation, source-identity change detection, fresh
pre-dispatch revalidation, native postcondition review and read-only
uncertain-dispatch reconciliation. An independently reobserved desired
value, original value, or indeterminate value is **never permission to
redispatch** or proof of causality. The durable transaction owner must
separately establish a consumed one-shot attempt before any execution.

The backlight::kernel reader observes the real /sys/class/backlight
class with bounded enumeration, root-owned sysfs provenance, fixed
native attributes (type, max_brightness, brightness,
actual_brightness, bl_power), native bounds and a second complete
sampling. It rejects noncanonical paths, virtual class devices,
non-sysfs facts, swapped objects and inconsistent readings.
It never writes any sysfs attribute.

The native session observer independently reopens the exact logind
session through the authenticated unique root-owned D-Bus owner and
rejects stale, inactive, remote, greeter, non-Wayland or wrong-UID
sessions. It returns a scoped native observation **not** a principal
authentication, approval or privilege grant. The backlight::candidate
adapter correlates these read-only sources, rejects zero or multiple
physical devices and rechecks owner, boot, session generation,
seat, UID and kernel snapshot.

An additional read-only **user-subject candidate** now verifies the
current D-Bus connection UID and PID and requires GetSessionByPID to match
the exact original logind session before and after observation. It rejects
root and same-UID processes running outside that login session. This is
preparatory for a future subject-bound executor, **not a permission to
call SetBrightness or a substitute for physical calibration**.

Kernel inode, device path, native class name and reported logind
session are useful correlations, **not** sufficient device-generation,
hardware-seat ownership or authenticated caller proof. The candidate
API cannot mint approved effects. It does not assert safe-minimum
calibration or independent post-write success.

## Original-caller integration

`Authority1.GetOwnNativeBacklightCandidate` now retains the original unique
system-bus sender, authenticated bus GUID and numeric PID separately from Actor provenance. Its native
probe requires the authenticated broker's `GetConnectionCredentials` reply to
include matching `UnixUserID`, `ProcessID` and a live Linux `ProcessFD`. The
adapter retains that descriptor across both kernel samples and verifies its
kernel fdinfo PID and liveness. It never synthesizes caller proof by reopening
a numeric PID. Missing ProcessFD support is unsupported, with no UID-only
fallback.

Both native samples require `GetSessionByPID` to resolve the original process
to the exact owner-observed session object and original `SessionEpoch`, before
and after reading active/local/Wayland/user/seat facts. Connection credentials,
root-owned unique logind owner and boot are freshly rechecked. A background user
service outside the selected login cannot borrow its UID to satisfy discovery.
The existing UID-only correlation helper remains explicitly non-authorizing;
Authority1 no longer uses it to claim original-caller scope.

One original two-second budget spans connection, credentials, native session
and kernel reads. It uses suspend-inclusive BOOTTIME and rejects wall-clock
regression/expiry as well. Each RPC receives at most its existing 750 ms bound
and only the remaining aggregate time; timeout or a late reply cannot renew
freshness. Native RPC bodies and descriptors are bounded before decoding.
The candidate retains the original acquisition time internally. The public
`(ssuuu)` reply remains diagnostic and carries no durable freshness or mutation
credential.

These are caller-scoped observation checks, not protected worker attestation.
A future executor must still prove immutable worker invocation, same-UID
isolation and protected, single-use durable handoff under ADR 0046. The current
root executor cannot acquire brightness authority from this observation.

### Automated checks for this increment

The affected suites cover root/wrong UID, missing/mismatched PID, forged
Actor provenance, nonunique sender, absent/wrong-typed broker credentials,
non-pidfd descriptors, native process exit, PID mismatch, clock regression,
suspend/expiry and existing session/source/unsafe-value negative cases.
The real pidfd lifetime test uses a disposable process and reads only kernel
metadata; it is not physical backlight qualification. Exact-head canonical,
Security/CodeQL and inherited native workflows remain independently required.

## Canonical managed data and observe-only recovery

`linura-core::BacklightResourceId` now binds the exact `SessionEpoch` and a
nonzero canonical physical device-generation UUID. It rejects root/invalid UID,
ambient sessions, partial or aliased resources and names/paths/inodes used as
generations. Parsing is not attestation: no production inventory currently
issues these generations, and a caller-created UUID supplies no lineage proof.
Seat, provider generation, safe bounds and qualification revision remain
material canonical observation evidence; they cannot be omitted during future
native integration.

Control's proposed effect codec carries only that exact resource and one
canonical native integer. Decoding rejects a different provider/method/resource,
extra or duplicate parameters, malformed/boundedness violations and unsafe
values against independently supplied current bounds. It cannot select a
native object path, kernel filename or alternate method/subsystem. A descriptor
is data, never an `AuthorizedEffect` or dispatch permit. Both the live registry
and the sealed managed effect factory still reject the route.

Canonical risk review classifies only the exact resource/provider/capability
and native-value shape as `SecuritySensitive`, requiring administrator approval.
A lower floor cannot downgrade it. Durable candidate/recovery handling also
requires the authenticated `unix:uid:<original-uid>` independently of Actor.
For this provider, the durable authority boundary refuses recovery modes that
could reprepare: even fresh administrator approval cannot turn an uncertain
attempt into permission to replay. The internal observe-only path may verify,
remain indeterminate or block based on fresh evidence.

Level A domain tests exercise the canonical planner, policy, signed reservation
and recovery against a recording transaction-store port. They cover prepared
abort on Control reconstruction, consumed-attempt retention, duplicate handoff,
original/desired/competing observations, unavailable evidence, changed request,
foreign/root principal, and attempted approval-based reprepare. They explicitly
simulate retained state and do **not** prove SQLite crash durability, native
worker execution, protected IPC or physical visibility. Existing concrete
SQLite/VM gates remain required; future composition must qualify the complete
backlight route against them.

### Concrete SQLite/WAL one-shot persistence regression

The production `SqliteTransactionStore` now has S21-3-specific regression
tests using a canonical original-user/physical-device resource and a
synthetic, SecuritySensitive administrator-approval binding. They persist a
signed Prepared-to-Indeterminate reservation, close and reopen the real
database, reject a duplicate signed dispatch and a changed hardware-generation
binding, retain an ambiguous observe-only resolution across a second reopen,
and validate database integrity. They **do not** establish that this binding
came from an approved live Control candidate, that a protected user-session
worker exists, or that any physical backlight was safely operated.
The separate domain recording-store tests continue to cover Control's
policy, subject, risk and no-reprepare decisions. Full protected native
composition, real restart fault injection and Level C/Q11 remain required.

### Fail-closed below-minimum baseline

Native pre-dispatch review now rejects an **already sub-minimum original
physical brightness level**, even when the newly proposed target is at or above
the independently supplied visibility floor. The same original-level
invalidation propagates through read-after-effect review, uncertain-outcome
classification and restoration observation. Negative tests cover dark native
baselines of 0, 1 and one unit below the example minimum. This is a
**read-only safety invariant**, not proof that the floor was calibrated,
the physical panel was identified, or recovery is available. An already dark
screen requires an independently qualified external recovery path rather than
permission to perform an unqualified managed brightness mutation.

## Integration order and remaining dependency

The read-only discovery and canonical backend data can be developed on `main`
independently of PR #259. They do not consume its unfinished display mutation
implementation. [ADR 0045's sequence](../adr/0045-s21-workstation-device-authority.md)
is S21-2 display before S21-3 brightness for integration/merge. Accepted display
identity/topology and visible-access/hotplug requirements must be reconciled
before qualifying executable brightness; this ledger does not declare that
integration complete. PR #259 acceptance also cannot supply the separate
original-user worker or physical backlight evidence required here.

## Maintained physical enrollment procedure

Use the [physical backlight enrollment and safe-minimum acceptance procedure](v0.10.0-s21-3-physical-enrollment.md)
for exact hardware/seat/panel lineage, independent visible floor calibration,
externally demonstrated recovery, protected original-user dispatch and
Level C/Q11 evidence. This is an **unexecuted procedure**, not enrollment proof.

### Inactive original-user native mechanism

`linura-authorityd::original_user_backlight` contains a separate **inactive concrete composition-layer** system-bus worker mechanism. It checks its own real/effective non-root UID,
original bus sender and kernel ProcessFD/session evidence, revalidates the
exact resource and native safe-bound precondition, and defines only the fixed
logind `Session.SetBrightness("backlight", inventory_device, value)` call.
Its non-cloneable one-attempt worker always consumes its attempt before
native dispatch. **No production issuer for the opaque
`QualifiedBacklightAttempt` exists**, and no runtime calls this method;
therefore this module is **not** protected supervisor attestation, qualified
interprocess handoff, a live mutation or accepted physical execution. It
deliberately does not register a service, add systemd execution privileges
or allow root to substitute its D-Bus caller. Before activation, implement
the separate protected supervisor/worker image and channel, enforce same-UID
tamper resistance and native caller authentication end-to-end, bind accepted
physical generation/floor to the grant, and qualify exact-source dispatch
and Q11 evidence.

### Control-owned one-use effect admission (inactive)

The concrete Authority1 composition package now has an inactive
`backlight_handoff` admission module accepting only Control's sealed
`AuthorizedEffect` (which contains the consumed durable `DispatchPermit`).
It checks exact canonical backlight target, native bounds, effect provider,
method, payload and dispatch-correlation integrity before projecting a
non-cloneable in-process admission object. Adversarial tests reject changed
device generation, method, provider, payload, non-qualified numeric bounds
and forged generation, transaction, state version and authority-use digest.
This is **not** a credential issuer, a cross-process protected channel,
qualified hardware identity, a native dispatch or operation registration:
the resulting object has no path to `QualifiedBacklightAttempt`. The
real protected worker, exact one-use IPC, source-attested minimum, original
caller proof and independent physical verification remain release blockers.

### Native lost-reply ambiguity

The inactive original-user mechanism now labels *any* error returned by an
attempted logind `Session.SetBrightness` call as
`IndeterminateDispatch`, not pre-dispatch `ProviderUnavailable`.
A regression test proves that a lost reply cannot be mistaken for a safe
no-effect refusal. The worker consumes its one process-local attempt before
the call. This is **not** complete cross-process no-replay durability or
native success verification; those are still required.

### Protected original-user process observation IPC

The existing supervised `linura-security-owner@.service` is a
non-root, AT_SECURE, non-dumpable, root-owned-image **per-UID system
service**. Its own PID is not established as a member of the graphical
login's logind Session. Its protected IPC proof therefore cannot serve
as the original-session `SetBrightness` caller credential. Its
private D-Bus endpoint now exposes **read-only**
`ObserveBacklightOwner() → (sessionLock, sampledBootMs)` solely through
the existing authenticated Control peer boundary, with independent
`currentSession()` reobservation, exact active native login and owner
invocation, new peer reattestation and a strictly exclusive two-second
BOOTTIME freshness check. The native test verifies the on-wire structure,
invalid identity, expiry and clock regressions. The established per-user
system-bus policy is unchanged; no extra public listener, untrusted
same-UID caller permission or root-origin backlight write was added.

Control's `NativeSessionChannel::observe_backlight_owner(lock)` now
consumes the new protected-process method on the **same canonical trusted
Control system-bus connection**. It independently rediscovers the exact
systemd-supervised security-owner PID/invocation/unique sender, validates
the two-field `(st)` response and original session/lock generation, checks
suspend-inclusive BOOTTIME expiry, then revalidates the same native owner
and boot. Its negative tests reject changed generation, UID, boot,
malformed resource, stale/future timestamps and zero timestamps.
No caller-synthesized worker invocation or D-Bus name is accepted.

The concrete Authority1 composition's
`BacklightAuthorizedHandoff::from_control_with_protected_owner` now
requires a matching exact login epoch and calls the trusted Control bus's
fresh `observe_backlight_owner` before projecting the already sealed,
durably consumed Control authorization. A wrong user/epoch or unavailable
protected worker fails closed without minting a replacement permit.
Negative tests assert wrong-UID original session denial. The
`from_control` helper is **private** to the admission type and is callable
only after the public worker-bound constructor has required the protected
native session proof. No other constructor permits a bypass. This remains
data-only, and production activation still requires independently qualified
hardware, a protected one-use mutation IPC and verification.

**Limit:** this proves only authenticated *security-supervisor availability
and observed login identity*. It is NOT proof of the original login's
actual kernel-bound D-Bus caller. The separate protected **session-member
worker**, proof of its actual PID/session, and one-use handoff are still
required. It is not yet a protected one-use mutation handoff, immutable
brightness grant, physical panel/seat qualification or independent actual
brightness. Its output must never be interpreted as permission to dispatch.
A later integration must bind the sealed Control effect to the exact
supervised invocation and preserve durable, protected consume-once semantics.

## Original-user native deadline hardening

The inactive original-user mechanism no longer inherits the native session
channel's sixty-second interactive timeout. Its private native calls are bounded
by the lesser of 500 ms and the remainder of one original two-second deadline.
That deadline uses suspend-inclusive BOOTTIME plus wall time, rejects regression
and exclusive expiry, and is checked before polling a request and after receiving
and decoding a reply. A partial clock regression cannot renew a previously
shortened budget; a ready reply cannot win a scheduling race after its RPC cap.
The subject probe retains its 750 ms RPC cap under the outer remainder.
Connection, original-sender credentials, session lookup,
PID membership and both kernel samples receive only the remaining discovery
budget; the existing two-second discovery cap can be tightened, never extended.
Native replies are bounded before decoding and cannot carry file descriptors.

Every mutation reply failure, including a timeout, expired or malformed reply,
remains indeterminate after the process-local attempt is consumed. The tests
exercise expired futures without polling, stalled RPCs, suspend/clock change,
caller budget tightening, oversized replies and unexpected real descriptors.
These are adapter/component tests: the opaque `QualifiedBacklightAttempt` still
has no production issuer, and no native mutation, protected process bootstrap,
physical calibration or Level C/Q11 acceptance is established.

## Next integration checkpoint: accepted S21-2 contract

The next **qualified dispatch admission** must consume the accepted S21-2
output/topology and protected-owner safety contract from PR #259. In particular,
it needs one authoritative binding between the original session/seat, compositor
and output generations, the physical backlight/panel, current powered/visible
outputs, lock coverage, and active display-change/recovery fencing. A logind
session ID, a physical class name, a new UUID or the protected supervisor's
read-only availability reply cannot supply that binding.

PR #259 owns the candidate `DisplayTopologyId`/`DisplayOutputId` lineage and
native display/lock/power/recovery coordination. Those contracts and their native
qualification are not accepted in `main` yet. Do not invent another topology
observation envelope, guess its final wire shape, issue executable worker grants
from the current supervisor observation, or have the root S17 executor perform
brightness changes to bypass this checkpoint.

The protected original-login process bootstrap and immutable invocation proof,
durable consume-once cross-process mutation IPC, production native verifier and
complete live Control lifecycle remain unfinished. They must be composed and
qualified against the accepted display safety contract; this checkpoint is not
an attestation that those P0 items are already implemented. Hardware generation,
positive visibility calibration and independent external recovery remain
additional required evidence after the contracts are available. Writes and live
registration remain disabled while waiting.

## Work required before enabling any write

1. Establish supported physical panel/seat mapping with driver,
   udev and hardware evidence; reject aliases, unrelated devices,
   hotplug replacement and sole-output blackout.
2. Qualify a conservative positive **nonzero native safe minimum**
   for each supported GPU, panel, driver and observed maximum.
   Reject unsupported hardware and missing actual-brightness evidence.
3. Integrate the canonical resource identity and proposed effect into the
   live trusted operation registry only after qualification; bind fresh physical
   lineage and the authenticated principal to the original active logind session
   and SecuritySensitive/Managed policy approval.
4. Implement a **narrow subject-bound** logind SetBrightness route.
   Never substitute root's D-Bus authorization for the user's own
   permission; no sysfs/CLI/DDC/gamma fallback.
5. Integrate the canonical durable prepare/dispatch reservation/reconciliation
   with the protected worker and concrete persistence; qualify a consumed attempt
   and no replay after transport uncertainty, restart or provider replacement.
   The domain observe-only guard and recording-store tests alone do not complete
   this integration.
6. Independently reobserve native requested/actual brightness and
   exact source generation **after** dispatch, never an executor reply,
   slider, cache or optimistic timer. Preserve an external recovery path.
7. Add typed Control/CLI/SDK/Quick Settings, OSD and hotkeys only
   through the same authority semantics; S21-6 owns presentation,
   S21-7 cross-domain integration.
8. Run exact-head build, fmt, Clippy, tests, security, adversarial and
   all protected regression checks without weakened gates.
9. Qualify maintained real hardware with Q11 Level C evidence,
   including sole-panel dimming recovery, logind restart, hotplug
   and lost-response handling.

## Native adversarial matrix (obligations, not evidence)

| Category | Proof required before activation |
| --- | --- |
| Source forgery | fake files, virtual devices, swapped inode or sysfs mount rejected |
| Session authority | wrong UID, remote, inactive, recycled session and logind owner replacement |
| Device lineage | duplicates, stale maximum, hotplug and changed measured values |
| Authorization | user versus root subject; wrong risk, principal and effect denied |
| Durability | lost dispatch reply, journal restart and duplicates never blindly replay |
| Visibility | zero, below-minimum, sole-output blackout and failed recovery denied |
| Verification | independent read-after-write; ambiguity never committed |
| Environment | no physical backlight is unsupported; VM simulation is not Level C |

The matrix specifies acceptance obligations, not executed test results.
S17 lock/power, S21-2 display, S21-6 input/presentation and S21-7
integration are separate. Do not promote interactive_workstation.evidence_ready,
Q11 acceptance, release support or S21 convergence from this PR.
