# v0.9.0 security qualification — First Boot and exact reference environment

**Status:** release-readiness security review complete; terminal release-security evidence pending.  
**Claim class:** Experimental

## Security objective

v0.9 introduces an exact supported QualificationEnvironment and restart-safe machine-adoption path without allowing bootstrap, recovery, declarative provisioning, model output, imported Library state or qualification infrastructure to become an authority shortcut. The security contract is fail-closed across restart, cloning, rollback, owner handoff, security-baseline observation, migration/update recovery and release evidence binding.

## Primary threat classes

- corrupt, out-of-order, skipped or newer durable bootstrap state;
- rollback to an older previously valid bootstrap ledger;
- crash between external generation-anchor staging, ledger persistence and anchor finalization;
- cloning a prepared disk/state onto a different machine while retaining completed effects or owner-handoff state;
- malicious or substituted Provisioning Manifest, Setup, MachineProfile, source revision, observation or plan material;
- stale observations or durable planning state reused after source/target changes;
- caller-authored verification evidence used to complete an effectful stage;
- replay/substitution of effect verification between sessions, machines, stages or operations;
- fabricated, stale or replayed owner-enrollment/preparer-revocation receipts;
- recording `owner-enrollment-pending` while the real preparation principal still has process, group, SSH, password or sudo authority;
- false-negative firewall verification caused by an unrelated chain carrying a drop policy;
- active SSH exposure missed because a unit is disabled, renamed or listening on a nonstandard port;
- insecure APT source overrides expressed through one-line or deb822 syntax;
- qualification-only SSH transport contaminating or weakening production security observation;
- loss of the qualification transport across an intentional hard QEMU power cut, producing harness-only false failures or accidentally resurrecting canonical `ssh.socket`;
- recovery checkpoint substitution, corruption, incomplete durability or a checkpoint that cannot actually be restored;
- native-recovery evidence produced while First Boot remains available;
- SQLite backup taken without excluding writers or without folding committed WAL payload into the recovery image;
- stale WAL/SHM frames replayed over a restored database;
- migration semantic verification that omits released Library relations;
- package-update evidence manufactured by the same dispatcher or accepted without an independently observed post-state;
- interrupted/indeterminate package transactions blindly replayed after restart;
- unsupported host environment accepted because only distro/architecture were checked;
- release evidence assembled from missing, substituted or digest-mismatched shard transcripts.

## Required invariants

- Durable bootstrap history is integrity checked, machine/session bound and generation anchored outside the mutable state-root domain.
- Two-phase anchor/ledger updates are distinguishable and recoverable across expected crash windows.
- Prepared/effect-started restart states require authoritative re-observation; restart never recreates historical authority.
- Machine identity binds protected machine identity plus DMI hardware UUID; a cloned disk under a different hardware identity is rejected.
- Effect verification is issued only by trusted stage-specific producer boundaries in production and is exact-bound to session, machine, stage and operation.
- Planning cannot complete without the exact persisted source selections being revalidated and a deterministic non-authorizing plan binding being durably recorded.
- Provisioning manifests and imported Library objects remain untrusted declarative data and contain no generic commands or authority grants.
- Owner enrollment and preparer retirement consume authenticated HMAC-SHA-256 receipts with protected key handling, exact binding and consumption-time freshness checks.
- Deferred handoff cannot complete until the actual preparation principal has lost its qualifying OS authority.
- Q8 evaluates the actual nftables input chain, active/enabled SSH-serving units and listener-owning SSH server processes on every port, plus insecure one-line/deb822 package-source overrides.
- Qualification transport is isolated from the product observation boundary; production verification contains no qualification bypass.
- Every intentional hard-cut transport handoff verifies persistent masks/generator override/transport enablement and executes a durability `sync` before power loss.
- Recovery checkpoint verification strictly parses the canonical manifest and validates ledger/session/anchor content and exact digests before stage completion.
- Native recovery is demonstrated with First Boot and network/model dependencies unavailable.
- SQLite recovery backup holds writer exclusion across checkpoint/copy/validation and restores without stale WAL/SHM replay.
- Migration semantic fingerprinting covers the complete released Local Library relation surface and authority transaction state.
- Update verification is produced independently after authoritative package post-state observation and cannot be self-attested by the dispatcher.
- Unsupported QualificationEnvironment substitutions fail closed rather than inheriting support.
- Canonical adversarial evidence is accepted only after every expected shard, role, boundary range, environment, source, binary/workflow binding and transcript digest agrees.

## Release-blocking security conditions

Release security remains blocked if any release-authorized source can:

- resume/replay effect or owner authority from durable state alone;
- accept rollback/corruption/newer bootstrap state without explicit safe recovery;
- carry prepared history onto a different machine identity;
- complete planning without exact source revision and fresh observation binding;
- self-attest effect verification, owner enrollment or preparer revocation;
- retain actual preparer authority after a deferred-owner handoff is recorded;
- accept inbound firewall exposure, active SSH service/listener or insecure package source as a verified baseline;
- accept an arbitrary file or incomplete bundle as a recovery checkpoint;
- claim native recovery while First Boot/network/model remains required;
- lose committed SQLite semantic state during backup/restore/migration;
- blindly replay interrupted/indeterminate package effects;
- accept unsupported environment substitution as the v0.9 QualificationEnvironment;
- assemble release evidence with a missing/substituted shard, transcript, binary or workflow binding;
- regress any inherited v0.4–v0.8 authority, durability, executor/verifier, managed-lifecycle, Library or proposal-only invariant.

Terminal security evidence must be recorded only after final exact-head and release-authorization runs actually succeed.
