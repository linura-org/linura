# v0.10 S22 qualification — screenshot, recording and clipboard history

**Status:** Proposed native acceptance, not an executable feature, release result or physical evidence.
**Profile:** `arch-hyprland-v1`; declared S16 predecessor.
**Contracts:** [ADR 0051](../adr/0051-s22-protected-desktop-utilities.md), [inactive S22 design](../../contracts/v010-s22-design.toml), [security acceptance](v0.10.0-s22-security.md).

## Evidence and support claims

S22 is a Q9–Q14 subdomain contract. A real capture/recording/clipboard acceptance report must bind exact Linura source and installed capture adapter hashes, pinned Hyprland/portal/Wayland/PipeWire/provider versions, kernel boot, owning UID/logind session/seat, compositor epoch, S17 native protected-session state, target topology/geometry and native offer/capture/recording generation. Every claimed external effect requires original typed request, trusted class/risk/policy, same principal, independent postcondition and source/digest-bound artifacts. Recording of a CI desktop is evidence of that recording only; it does not establish protected exclusion, user consent, physical rendering or Q11.

### Operation-class evidence

Proposed external screenshot, recording, export and clipboard writes are intentionally disabled conservative managed candidates. A later transient claim requires separately reviewed unprivileged at-most-`UserState` risk, bounded native post-effect proof, canonical-plan authorization and durable audit without durable indeterminate recovery. History policy and deletion are `LinuraOwnedState` with authenticated revisioned local transactions rather than fake OS mutation. Sensitive reads require explicit purpose-bound access independent of general observational cache and cannot be silently disclosed to agents. Unsupported target/grant/secure exclusion must fail closed, never invoke hidden fallback.

For each activated managed effect test request/observe/plan/validate/authorize/prepare/execute/verify/commit/audit/reconcile, plus changed origin/target/consent, no-change policy, pre- and post-dispatch crash, portal request accepted but canceled, lost reply, partial file, recorder orphan, expired source and no-blind-replay. A portal session handle is not a Control authorization or proof the recording is truly active.

### Evidence tiers

**A — automated exact-source Arch/Hyprland VM:** Native compositor + actual installed portal backend with controlled real screenshot/ScreenCast, PipeWire and clipboard offer; compositor lock/protection transitions, multi-output/scale where reproducible, external independent validation of frame exclusion and file/recording ownership. Mock screenshot byte arrays are unit tests, not native Level A.

**B — interactive VM:** Same pinned runtime and source, actual user-driven target selection, protected consent, recording status/stop, clipboard opt-in, keyboard/pointer/screen-reader/reduced motion/scale, recoverable errors. A recording of the UI is not proof of correct protected frame exclusion.

**C — maintained physical workstation/Q11:** Actual supported GPU/driver/monitors, HiDPI/multioutput/hotplug/lock coverage and real input/clipboard provider, secure capture denial across protected session, physical screen recorder stop and accessible first-party interaction. Source/boot/seat/compositor artifacts bind external Q11 controls. Physical proof remains pending until retained independent evidence passes all requested cases.
