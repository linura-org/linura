# v0.10 S22 security qualification — protected capture and clipboard confidentiality

**Status:** Proposed adversarial contract. Neither native protected capture nor protected persistent history has been qualified.
**Authority:** [ADR 0051](../adr/0051-s22-protected-desktop-utilities.md), [domain acceptance](v0.10.0-s22.md), [threat model](../threat-model.md).

## Security objective

A session app, stale compositor handle, untrusted portal request, background clipboard observer, compromised screenshot URI, mistaken filesystem target or model-generated action must not reveal protected screen/clipboard content, record another session, turn consent into reusable effect authority, create unbounded hidden recording, or persist secrets in history/audit. Denial must occur at the **native enforcement boundary**, not only in UI decoration.

| Attack or failure | Required adversarial execution | Independent denial/recovery oracle |
| --- | --- | --- |
| Lock transition during frame | Begin screenshot then lock during capture readiness | No protected frame bytes reach private staging |
| Protected authentication | Capture through S17 native password/consent or secure-input surface | Capture blocked by compositor/portal enforcement; never posthoc masking |
| Clipboard while locked | Read/history monitor during S17 lock/login or different seat | Access denied/paused; no old offer replay |
| Fake compositor owner | Replace Hyprland process/socket or session/boot while request pending | Owner/seat/compositor epoch mismatch |
| Multi-output hotplug | Remove/rotate/scale/swap outputs during region/window selection | No wrong-output content, crop or stale authorization |
| Portal sender spoof/revoke | Wrong session-bus peer, canceled Request, revoked grant or reused restore token | Trusted portal owner/current request rejects; no persistent hidden grant |
| Bypass portal | Launch raw `grim`/`slurp`/`wf-recorder` on permission failure | No shell or alternate fallback route |
| Arbitrary Wayland capture | Direct ext/wlr screenshot protocol exposes secure source | No activation absent proven native exclusion of protected pixels |
| Hidden recording | UI crashes, loses focus or compositor lock while stream continues | Independently supervised native revoke/Stop; no orphan recording |
| Recording stop substitution | One user tries to stop/use another caller's stream | Exact capture-session/owner token and source epoch |
| Recording audio escalation | Video selected without microphone/loopback capture consent | No audio source attached; S20 permissions remain separate |
| File path substitution | Symlink/hardlink, traversal, unsafe permissions, file replaced after review | Safe open descriptor/ownership/atomic publish, no secret leak |
| Retained temporary content | Crash before save/export, oversized frame, disk full or encoder failure | Private bounded staging and verified purge/recovery |
| Clipboard foreign-seat injection | Offer on different wl_seat, reused serial/owner or spoofed MIME | Exact seat/offer/selection epoch, bounded MIME parsing |
| Clipboard type confusion | Huge HTML/image/MIME, markup or dangerous file URI | Strict allowlist/size/time, sanitized presentation; no arbitrary fetch |
| History without consent | Default-on store, silently persistent monitoring, false encrypted label | Owner opt-in and independently reviewed key lifecycle |
| Secrets entering history | OTP/password-manager offer or raw protected selection | Source exclusion policy/uncertainty denies persistence; no secret-content logging |
| History key/DB compromise | Unsafe key ownership, plaintext database, wrong-user restore | No persistent support unless protected key and store proven |
| History delete race | New offer arrives during clear, stale revision after suspend/logout | Cancel producers, atomic revision and verified logical removal |
| False secure shredding | SSD/COW/snapshot retains unlinked clipboard database | No unsupported physical-erasure claim |
| Agent exfiltration | Model requests clipboard/capture or screenshot-share auto upload | No general model access or implied upload permission |
| Optimistic visual feedback | Portal returns handle but no frame; Stop reply but stream active | Native status/outcome separate from receipt |
| Audit/media leakage | Raw screenshot/clipboard values in logs, audit, Q10 videos/notifications | Only safe metadata, never content bytes |
| Host/VM confusion | VM screenshot passes but physical GPU/secure input untested | Scope remains Level A/B, not Q11 |

## Independent failure windows

Exercise before consent, after portal request but before native source/stream, after native frame but before private staging, after staged bytes before safe destination, after recording Start but before indicator, after UI/portal/compositor/encoder crash, after Stop request with live stream, after clipboard policy revocation and during history deletion. Uncertain effects must be represented as indeterminate and reconciled using actual live portal/compositor/PipeWire or local-store state; never silently repeat a prior capture or upload on restart.

**No compositor-verified protected-surface exclusion = capture unsupported. No supervised native recording stop = recording unsupported. No protected retention/key handling = persistent history unsupported.** Degraded modes must not quietly substitute unreviewed native tooling.

Media, plaintext clipboard bytes, OTP/secret values, screenshots of protected input, raw path names and untrusted portal diagnostics must not enter model, plans, audit, retained qualification recordings or general notifications. Retained native evidence must bind source SHA, user/seat, compositor epoch, protected transition, provider identity and externally controlled expected denial.
