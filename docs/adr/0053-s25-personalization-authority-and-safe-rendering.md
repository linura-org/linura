# ADR 0053 — S25 versioned personalization, safe assets and renderer authority

- Status: Proposed
- Scope: v0.10 S25, `arch-hyprland-v1`, declared predecessor S16
- Refines: ADR 0017, 0018, 0031, 0032, 0033 and S17's ADR 0042; preserves S21 display authority
- Companion: [inactive design](../../contracts/v010-s25-design.toml), [domain qualification](../qualification/v0.10.0-s25.md), [security qualification](../qualification/v0.10.0-s25-security.md)
- ADR number provisional to the independent WIP branch; reconcile with the append-only ADR ledger during implementation PR extraction.

## Context and decision

The existing `design/tokens.json` defines semantic roles, typography sizes, motion durations, control/icon metrics, spacing and radii. The compiled internal `org.linura.UI 1.0` SDK provides actual shared QML controls and `LinuraTheme.qml`, currently bound to a `SystemPalette` plus fixed semantic danger/warning/success roles. This is **existing first-party presentation infrastructure**, not a live persisted theme configuration or systemwide wallpaper manager. Existing Shell, Control Center, Quick Settings, First Boot and S17 protected security-owner consumers must retain their current authority boundaries.

**Decision:** Separate a typed, versioned and owner-authenticated **Linura-owned preference document** from ephemeral previews and from any **external compositor/desktop setting effects**. The preference commit must be a revisioned atomic local transaction; it must not imply that every UI surface or wallpaper backend has rendered the chosen change. A cross-surface renderer reports the **actual applied revision** and effective safe tokens, with explicit unsupported/failed/degraded states. The accompanying TOML describes inactive candidates only: no runtime registration, preference mutation, plugin activation, lock screen override, changed S10/S16 source behavior or Q10/Q11 promotion.

### Preference ownership and revision

Bind authenticated local user, logind session/seat where application is session-scoped, boot where native provider identity matters, schema version, canonical typed preference key set, origin, base revision/digest and monotonic committed revision. Use compare-and-swap and an atomic bounded local persistence model with owner-only permissions, safe file descriptor/path, sync/durability policy and appropriate rollback or recovery. Unknown and newer schema versions must fail closed; migrations are explicit versioned transformations with preserved prior revision and tested recovery. An imported Setup/MachineProfile or workflow is data, never consent, executable UI code, role, principal, policy, or direct theme authority. Avoid distributing preferences across multiple independent, inconsistently writable files.

Distinguish **draft/preview** from **committed preference** and **renderer applied state**. Preview is `ExperienceEphemeral`: one current authenticated session + window/target + preview generation + bounded TTL, deterministic cancel, no persistent file change or compositor effect. Cancel/restart/lock/sign-out must not persist draft or replay external effects. A saved revision is `LinuraOwnedState`: an actual atomic owner-authenticated commit with independent revision/readback, not a QML optimistic notification. Apply to a renderer is a separate derived presentation/observation flow; where it changes a native provider outside Linura's local state it is an external effect with an independently registered Control contract.

### Design tokens and cross-surface consistency

Retain `design/tokens.json` as vocabulary and `org.linura.UI 1.0` as first-party implementation. Adopt a typed semantic token schema that preserves background/surface/foreground/muted/accent/danger/warning/success/focus and accessible highlighted text, spacing, typography, density and motion without allowing consumers to supply executable QML, JavaScript, CSS, shader expressions, markup, URLs or arbitrary Qt property paths. Validate palette and interaction contrast under actual compositing/transparency/color roles, keyboard focus and disabled states; protected error/denial/security/recovery states cannot be hidden or recolored into apparently successful status. Accent changes cannot override failure/warning/success semantic meanings or authorization/confirmation chrome. Reduced motion must be enforceable globally and cannot be overridden by an imported theme.

A `SystemPalette` change does not establish a shared application preference revision, and distinct `LinuraTheme` instances currently need a versioned shared projection rather than per-panel mutation. Renderer consumers (Shell, Control Center, Quick Settings, OSD and, where scoped, First Boot/installer) must apply the same source revision or explicitly show why a privileged/security surface uses its independent verified safe palette. Do not modify secure lock/authentication visuals through arbitrary user themes: the S17 protected security owner retains its packaged fontconfig and immutable secure-input semantics. Even a valid local preference cannot override S17 keyboard focus, password secrecy or screen lock controls.

### Font, icon and wallpaper safety

A font-family choice is a reference to an **installed, validated system/user font family with bounded fallback**; it is not an instruction to install packages, write fontconfig globally or inject a font file into the protected S17 authentication process. Unknown glyph coverage, missing font, script/RTL and accessibility must degrade to an approved fallback with an explicit effective result. No arbitrary remote font, bytecode or user `fonts.conf` inclusion.

Icon family selection is an installed allowlisted theme/resource reference with bounded image and metadata handling. An icon name or filename from imported config is not a path authority. Do not treat SVG/script/foreignObject/external references, symlinks, remote URLs or unsandboxed arbitrary image plugins as automatically safe. Constrain MIME, dimensions, encoded/decompressed byte budgets, frame count, formats, source trust and image parsing. External icon theme installation is a separate S23 package/trust decision, not an S25 preference side effect.

Wallpaper is a potentially sensitive **untrusted local file**, not a trusted QML or compositor command. Resolve with owner-scoped safe descriptor, reject symlink/race/hardlink where necessary, confirm regular file, size/dimension/decoded-pixel/animation/resource limits, content hash, supported MIME and actual decoder safety. Reject remote/file URI schemes and shell/compositor configuration fragments; the filename or URI is not an executor grant. Store stable content/digest reference according to an approved user-owned asset lifecycle, not a stale path that can silently replace bytes. Preview/crop/fit/per-output choices are purely presentation until explicitly authorized to an external wallpaper provider. Per-output intent must bind current S21 output topology/geometry and immutable source bytes, including hotplug/scale/rotation.

### External effects, compositor and system theme

An authenticated preference *save* does **not** authorize changing Hyprland, GTK/Qt application environment, icons/fonts packages or S17 lock UI. Native wallpaper apply/clear and any actual desktop appearance/color-scheme protocol write are separate candidate `ManagedExternalEffect` operations, conservatively security-reviewed and **disabled**. Reevaluate a narrower `TransientExternalEffect` only if unprivileged, at-most-`UserState`, fully bounded without durable unknown/replay and independently verifiable under exact user-session and provider epochs. Missing provider or unverifiable postcondition => explicit unsupported; no `hyprctl`, `swww`, `wallpaperctl`, `gsettings`, arbitrary Qt method, `sh -c`, shell, QML or D-Bus forwarding fallback.

For each future managed effect require typed trusted operation/risk, authenticated real session principal, canonical plan, current target and provider revision, policy approval, durable prepare, narrow native adapter, independent fresh applied-state verification, commit, audit and reconcile. `policy allow != executor grant`; `reviewed plan != prepared mutation`; `executor != verification`. A committed preference and an externally failed renderer are **two distinct states**. Partial renderer application, compositor restart, lost receipt, output replacement or crash retains degraded/indeterminate native effect and observe-only recovery; never silently replay stale approval or promise all surfaces changed. Restore a previous *Linura-owned revision* through new authenticated CAS; external reversion is a new qualified and verified effect, not an assumed inverse.

### Interaction and qualification

Control Center personalization, shell/Quick Settings, preview pickers and CLI/SDK display the same typed preference revision and actual per-surface effective renderer status. Provide explicit Apply/Cancel, undo/revert where supportable, preview expiry, chosen fallback, keyboard/pointer/assistive navigation, focus, RTL/locales, contrast, reduced motion, font scaling and multi-output HiDPI. No-model/offline configuration is first-class.

[Domain](../qualification/v0.10.0-s25.md) and [security](../qualification/v0.10.0-s25-security.md) dossiers specialize Q9–Q14. Actual Qt/Hyprland rendered pixels, keyboard/a11y and failure diffs must be retained under existing digest-bound Q10 visual controls; synthetic static token tests cannot replace actual visual, interactive or physical Q11 evidence. The contract changes no production runtime, register, ledger completion or support claim and mandates adaptive PR extraction by real dependency/authority/qualification seams.
