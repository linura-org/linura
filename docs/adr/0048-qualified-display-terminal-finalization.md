# ADR 0048: Authorize display terminal finalization separately

- Status: Proposed
- Refines: ADR 0012, ADR 0018, ADR 0032, ADR 0046 and ADR 0047
- Scope: S21-2 terminal workflow; production display mutation remains unavailable

## Context

The original-restoration `LNRI:1` operation deliberately returns nonterminal
status with startup, input, opaque presentation, kernel and power protection
retained. Independent restoration proof and linked authority retirement do not
turn its old approval, committed snapshots or comparison receipt into permission
to release protection. Normal native Keep/Revert also require fence retention
through independent Control verification and layout commit.

## Decision

Introduce an explicit terminal managed operation with a separate fresh protected
authorization and canonical plan-bound durable prepare/revalidation. Its trusted
risk floor is SecuritySensitive. It is not a query, transient effect or mere
Linura-local cleanup. Root/native mechanisms remain narrow; Control owns planning,
policy, history, verification, recovery, dependency and retention decisions.

The private Experimental `LNRF:1` comparison material binds the restoration
request and dispatch, immutable original/restoration link, exact current restored
source guard, post-write epoch, current lock identity and unchanged complete
`LNRI:1` source material. Byte bounds, length framing, nonzero canonical digests,
complete original/replacement mapping and native capabilities remain mandatory.
The current lock must belong to the same replacement login. A newly authenticated
current owner/lock generation does not inherit approval from an older one.

The material is data. Its parser cannot certify a commit, authenticate a caller,
issue approval or release a fence. Old durable bytes retain their meaning; neither
an old restoration nor a historical receipt is a terminal execution credential.
The terminal path must load and authenticate both actual transactions and their
link, prove exact original retirement, and independently verify the complete
current native/source, Root, logind, coverage and physical frame facts.

The canonical terminal desired-state value is the existing purpose-separated
`LNRF-SHA256:1` digest payload. Complete bounded material remains in Control's
private authenticated context and must be recomputed against the digest before
planning and any later prepared handoff. This preserves the generic planner's
4 KiB attribute limit and avoids platform-specific validation in the planner.
A digest alone establishes neither historical context nor current proof.

The terminal operation follows the restoration layout commit and linked original
retirement. Its own effect handoff requires fresh protected approval, canonical
review, durable prepare, reservation/readback, current revalidation and a sealed
one-use adapter port. The protected purpose must be distinct from Apply, Keep,
Revert, original restoration, unlock and power. Generic preview or an untrusted
caller cannot supply its authenticated history context.

Native callbacks quiesce while all fences stay held. Root authenticates the exact
native sender on every acknowledgement fragment, verifies original protection,
and durably records qualified retirement before ordinary admission can change.
Intentional witness closure cannot poison an already quiesced native state. The
real S17 lock remains intact; held input is quarantined/drained before ordinary
focus. Fresh native source/frame checks remain necessary at the release boundary.

Historical completion cannot replace current admission. Lost acknowledgement,
spent-record repair, expiry, service loss and replacement races need explicit
qualified states, with no display-write replay, reconstructed witness or renewed
old window. A genuinely new effect needs a fresh managed authorization; it cannot
be reconstructed from the previous receipt. Committed original desired state needs
its own preserving adoption/continuation, never failed-baseline compensation.

Control analyzes shared ownership/dependencies before retention cleanup. Retain
unknown or still-referenced preimages and semantic why-chains; bound active,
retired and spent state with explicit full-storage refusal. No delete-to-retry,
unbounded retention or loss of provenance is permitted.

## Implementation and qualification limits

The initial implementation includes bounded core/SDK/adapter comparison codecs
and a read-only Control prerequisite inspection. The query authenticates both
actual requests, exact linked snapshots, phase records and original checkpoint
before provider probes, joins the same fresh five-source canonical restoration
proof, and reads the durable anchors again before returning an expiring report.
It performs no durable transition and cannot repair missing linked retirement.
An additional bounded Root query reads the actual immutable restoration
reservation while checking original live witnesses and current recovery admission
before and after readback. It shares the existing original-read worker. Protected
state requires live original protection; Reserved additionally joins this Root
invocation's retained memory to an exclusive immutable `LNRT:1` reservation and
its actual complete parent under the same locked scan. The actual-native channel
can advance that retained lifetime to Quiesced, with no retirement or release.
Control independently matches transaction/effect/dispatch
and checkpoint to authenticated history, joins the fresh canonical restoration
proof and preserves both original expiries. Closed future terminal comparison
states do not activate a Root retirement/release producer or supply release authority.
This initial inspection requires the exact restoration lock identity; current
owner/generation replacement fails closed. A fresh lock in the codec alone does
not qualify that path.

The owner's bounded terminal comparison reader now shares an exact `LNRF:1`
fixture with canonical core tests. It checks unchanged nested restoration,
purpose-distinct correlations and same-login current lock, and can compare a
restored native snapshot/source guard and post-write epoch. Changed public
aggregate fields are bounded before encoding. This arms no protected native
purpose and supplies no Root/physical-frame attestation or release authority;
existing Apply/Recovery parsers continue to reject terminal material.

The compositor additionally implements a private held-scene terminal review
transition. It accepts complete `LNRF:1` only over the actual consumed original
Recovery scene with its continuously live Root grant, matching restoration
transaction/dispatch, exact nested source, current lock, restored source guard,
post-write epoch and completed native safety frames. The full material travels
in an immutable sealed descriptor bounded to 14 KiB; mutable, oversized or
non-file descriptors are rejected before reading. The native integration identity
includes both readers. A new scope has fresh bounded wall/BOOTTIME deadlines and
all outputs need new configure/presentation evidence. It cannot renew restoration
execution authority, start standalone, repeat output writes or release protection.
After consumption, native content/input returns to opaque safety frames while the
one-use consumed correlation stays fixed. Root/source/clock/device checks and
permanent loss latches remain. Existing Keep/Revert keep their original bounds.
Separate native terminal authentication and prepared quiescence dispatch are
implemented. Root retirement/release remain unfinished; this mechanism does not
establish journal retirement or qualify native release.

The pinned scene accepts a separate one-use terminal quiescence request only after
actual terminal consumption. Its `LNFT:1` descriptor authenticates against the
continuously held original Root startup peer and binds complete reservation and
material, prepared correlation and original clocks. Current restored source/epoch,
no held input and fresh KMS hardware-completed opaque safety frames are checked
around the actual-native Root transition. Original witnesses remain continuously
required alongside the retained terminal channel. Replay or loss poisons further
continuation, retaining every fence. This is not durable retirement, release or
ordinary admission; actual native qualification remains required.

The private prepared handoff now connects the sealed typed Control port to the
actual supervised executor, one Root reservation and the protected owner's
consumed terminal scene. A separate default-deny service action protects this
mechanism. The adapter samples the restored desired layout/source; existing
Apply/restoration pre-effect checks remain unchanged. Complete material, canonical
transaction, native epoch and the generation after focus retirement must match
the consumed terminal receipt. It is spent before the single wire attempt. The
original two-second sample and absolute dispatch bounds survive every handoff.
Quiescence acknowledgement remains nonterminal; loss cannot reapprove, replay,
retire witnesses or release fences. Qualified lost-ack repair is still required.

The separate operation registration has ManagedExternalEffect semantics and a
trusted SecuritySensitive floor. Non-executable canonical planning requires a
private principal/request-bound context built from actual linked history; generic
previews refuse before provider probing. Planning re-observes Root reservation and
the same independent five-source restoration proof, checks exact current source,
post-write epoch and lock against complete material, then re-reads durable anchors.
It preserves the original provenance and performs no durable transition. Failed
planning retires the private context just as successful planning does.

Control additionally implements a separate typed terminal challenge/authorizer and
prepared one-use handoff. Full material must recompute the canonical digest before
protected review; actual linked history and independent facts are reloaded after
interaction. Exact fresh evidence remains bound into the refreshed candidate and
durable prepare. Volatile nested observation IDs and valid later physical frame
counters are evidence, not new human intent; only those already-validated finding
projections are normalized, with exact complete evidence retained in the terminal
observation digest. Source, post-write epoch, lock and lineage must remain equal.

Complete material is retained in a bounded versioned opaque journal record before
prepare. A separate small immutable owner record binds the restoration to one
terminal request/digest/material. Another operation ID cannot silently supersede
it; explicit qualified supersession remains separate. Request, material, owner,
reservation and dispatch readback precede the one-use port. Prepared/dispatched
duplicates never repeat approval or effects. Qualified v0.6 startup behavior still
aborts never-dispatched Prepared authority; this API cannot revive it.
Indeterminate duplicates return retained uncertainty, including after lost replies
or native refusal. No reply commits completion.

A separate read-only held-quiescence query authenticates the actual terminal
request, intent/claim, dispatched history and Indeterminate snapshot before any
provider probe. Root Quiesced must match its exact complete material and canonical
transaction/effect/dispatch. The same independent five-source restoration proof
must reconstruct unchanged source/epoch/lock/link material. Root is read again
after the join and all durable anchors are reread; validity intersects original
contributor expiries. The returned terminal snapshot and restoration evidence are
comparison facts, never retirement/release authority or terminal completion.

The native owner and Rust transport additionally implement a separate terminal
approval purpose (12) and fresh non-retained administrator action. The owner can
transition only its actual retained original Recovery flow on the same authenticated
Control connection, current login/lock and exact original material/request/dispatch.
It cannot create a terminal scene from historical bytes or a new owner connection.
The new review retains both fresh absolute clocks, complete material and canonical
request/observation/review binding, and needs fresh pages, frames and administrator
proof. The original spent Recovery receipt remains non-redeemable. Healthy consumed
Recovery retention no longer expires with the old output-write window; actual
native/Root continuity, original connection, monotonic clocks and bounded status
probes still govern that held lifetime. Loss never reconstructs or renews authority.
The typed Control finalization authorizer recomputes material's SDK payload and
resource, checks the exact principal/administrator class, and consumes that separate
native proof. Generic approval cannot substitute. The subsequent original
Root/native release, current qualification and final completion continuations
are described below; this approval mechanism alone provides none of them.

The private prepared executor endpoint acknowledges quiescence only. No public
production mutation is activated. Normal Keep/Revert physical release,
qualified successor/global-admission transfer, Committed adoption, safe
supersession and reference-aware cleanup still require coherent implementation.

Before activation, qualify the complete exact-source native failure matrix:
multi-output rules/overlays/modes/frames, compositor loss at each phase, stale or
lost proof, partial effect/lost replies, deadline/storage failure, current lock,
power/suspend/hotplug/focus/protected input and zero/one/multiple administrators.
Portable fixtures, compilation and historical green gates do not supply that
evidence. The PR remains draft until all remaining required work is complete.

## Stage 3 retirement/release state and crash-ordering contract

**Implementation status: partial, not qualified for release.** Control now
durably spends an exact one-use terminal-retirement preparation. Under the
existing Root admission lock, Root syncs the matching `LNRP:1` preparation
and `LNRH:1` RootRetiredHeld checkpoint while retaining the live original
witness, native scene, S17/input and power protection and ordinary startup
exclusion. Root also has an **unpromoted**, one-use `LNRN:1` native-release
reservation, with matching live Control/Root ownership, durable ancestry,
quiescence and readback under the existing admission lock. The supervised
Control-to-Root transport now accepts a separately committed, write-once
Control native-reservation decision after fresh RootRetiredHeld proof, captures
the exact original Control observation and immutable history, and reserves the
single Root LNRN:1 marker with authenticated pre/post readback. This decision
does NOT commit terminal completion, release physical protection or renew an
original clock. Once reserved, authenticated Root
`ReadFinalization` reports the distinct before-effect phase
`native-release-reserved` (wire 5); Control separately joins the exact
spent journal/Root/native held facts in a read-only lost-ack query.
This phase is **not** native consumption or release and cannot be confused
with `released-current` (wire 4). The original Control one-use spend decision,
authenticated Root `LNRX:1` native grant consumption, and pinned compositor
comparison-gate spending are now connected. After this separately authenticated
one-use spend and fresh native/KMS checks, the retained scene can schedule its
first ordinary presentation while **retaining input, S17, power, original Root
and startup fences**. Enabled heads retain the exact immutable submitted buffer;
disabled heads need their own fresh disable completion. Unrelated pending native
writes fail closed. This initial presentation is **not final fence retirement or
Control/Root completion**. A lost reservation/spend acknowledgement cannot authorize a
second grant. Neither `LNRN:1` nor `LNRX:1` means `ReleasedCurrent`.
The pinned-native `NativeFirstFrameGate` remains comparison-only: it requires
one spent attempt, original-clock freshness, exact topology/source continuity,
per-output hardware-completed ordinary frames or fresh disabled commits, and
**independent output-wide commit-result high-water**. Its accepted frame must
be the current output's latest native commit, not merely a frame-track event;
a substituted key, unrelated intervening native write or absent output history
fails closed. The actual compositor watchdog faults a spent gate after the
original window expires, even without an observer requesting the receipt.
No comparison result itself authenticates a later Root completion, retires
S17/input/power protection, or releases the startup fence.

The comparison gate additionally supports a distinct read-only reconciliation
after its one-shot first-frame observation. Fresh native/KMS inputs must match
the retained first completed commits, spend high-water marks, exact native
trackers and immutable buffer identities. It never reissues the original
observation or spends a grant. Missing evidence or drift permanently faults the
gate, including either clock moving backward within the original window.
The original deadline remains fixed. The sampler performs no effect. The
separately authenticated presentation attempt feeds its actual retained frames,
fresh same-output KMS and independent output-wide commit-result observations.

A distinct bounded `native_handoff_presentation` observation travels over the
same exact-source private Wayland connection and attested protected owner to
`display.native-handoff.observe`. It cannot be relabelled as opaque restoration
presentation. Its closed typed projection retains the original absolute wall
and BOOTTIME deadlines, full original/restoration/terminal lineage, source and
post-write/security epochs, connector/CRTC/plane/framebuffer identities and
spend/completion counters. Unknown fields, partial inventories, stale clocks and
non-recovery owner state refuse. Readback never renews the producer's window.

Control has a separate read-only post-effect inspection. It authenticates the
actual terminal, linked committed restoration and all three immutable Control
retirement/reservation/spend anchors before probing. It independently joins fresh
Root and original protection, current native source/layout, logind, S17 coverage
and first ordinary-frame observations. Original ownership, complete mapping and
restored source are derived from authenticated original history. A second native
read must reconcile the same first frames and original deadlines; fresh Root,
original protection and every durable anchor are rechecked afterward. The report
intersects the original source expiries and retained spend deadline. It cannot
create approval, commit completion, release any remaining fence or become a permit.
Actual native/adversarial qualification remains outstanding.

The initial spend method directly invokes that distinct post-effect inspection
after the sole Root/native port call and durable readback. Its typed successful
result is only the expiring inspection; the signed terminal snapshot stays
Indeterminate and no remaining fence is retired. A missing ACK or unproven first
frame returns Indeterminate. Subsequent work may inspect read-only, never repeat
the spent port or interpret a successful comparison as final completion.

An ordinary frame now has its own native tracker kind, distinct from opaque
safety frames and protected owner review/PAM content. Protected owner content
cannot satisfy the ordinary-frame comparison. The receipt carries both original
absolute deadlines; a later comparison timestamp never renews either window.

Control also retains bounded, process-local review material from the original
prepared canonical finalization. Before native grant spend it checks the exact
purpose, registered operation, current policy/risk, unchanged durable binding and
live original administrator approval. It removes the retained review before
durable spend and revalidates again immediately before dispatch. A restart,
revocation, expiry or lost review refuses this continuation; durable records
cannot reconstruct approval. This adds refusal checks to the existing
initial presentation protocol. It does not supply final input/power/admission
retirement authority or independently durable completion.

The remaining requirements below are an acceptance contract, not currently
implemented effect authority. The original-restoration terminal and ordinary
Keep/Revert paths must stay distinct even where they share low-level mechanisms.
No historical terminal or first-frame comparison may promote itself to
`PhysicalReleaseVerified` or `ReleasedCurrent`.

### Two independent safety barriers

1. **Durable Root/admission barrier.** Under the same serialized admission and
   checkpoint boundary as native startup, re-authenticate the supervised Control
   principal and actual Root-held original/replacement lineage. Persist an
   immutable, bounded, separately versioned one-use retirement reservation
   with exclusive sync and readback before *any* protection retirement.
   Retaining Control terminal history is necessary but not a Root capability.
2. **Physical native barrier.** The actual current, source-pinned supervised
   compositor consumes a distinct one-use release grant, validates continuously
   held lock/input/power/KMS protection and independently demonstrates correct
   output, rules/overlays, surviving root and hardware-completed frames.
   Temporarily lifting opaque coverage to observe first ordinary frames must
   *not* simultaneously release Root admission, S17 input or the inhibitor.
   Final input/power/admission handoff requires separately verified physical
   state and independently committed durable terminal records.

Root history retirement, native release, inhibitor retirement, input unlock,
checkpoint garbage collection and ordinary startup are separate, ordered
operations. A native ACK, historical receipt or comparison digest alone is
not authority for any of them.

### Required monotonic state ordering

| Design state | Retained evidence | Permitted effect |
| --- | --- | --- |
| Held | Original checkpoint, live witnesses and fenced native history | None |
| ReleasePrepared | Actual committed Control terminal history and exact immutable purpose-bound request | No protection retirement |
| RootRetirementPrepared | Root reservation serialized against startup, both owners and original history checked | No ordinary admission or unlock |
| RootRetiredHeld | Root retirement synced and independently read back; fences still held | Only one exact native physical release attempt |
| NativeReleaseSpent | Original authenticated native release grant spent before attempting effect | No retry, even after lost ACK |
| PhysicalReleaseVerified | Fresh native + independent KMS/frame/input/S17 evidence joined to unchanged durable anchors | Exact durable finalization only |
| ReleasedCurrent | Root and Control re-read matching final records while admission remains serialized | Qualified admission and reference-aware cleanup may proceed |

Final `ReleasedCurrent` completion and native fence retirement use the separate protocol below; successor admission remains lifecycle work.
Existing durable bytes and protocol versions keep their meanings.

### Distinct authorities

- **Original-restoration terminal:** require the actual linked original
  retirement and consumed separate terminal review; revalidate the same live
  original Root finalization/quiescence channel, restored native source, lock,
  epoch, checkpoint and authenticated Control history. Do not renew the
  original absolute clocks, recreate its witness or promote the held-quiescence
  inspection into an execution credential.
- **Ordinary Keep:** require Control Committed, matching Confirmed journal
  record, real native confirmed state, retained immutable checkpoint, fresh
  dual native observations and independent verification of the desired layout.
- **Ordinary Revert/expiry:** require Control RecoveryBlocked, matching
  Restored history, real native restored state and independently verified
  original rule/overlay ownership and baseline.
- The existing Control read-only inspections can guide refusal but cannot
  authorize release. A new purpose-specific authenticated authorizer must

### Crash, overlap and repair requirements

Startup, original witness retention, terminal reservation and retirement
writers must share a checked serialization protocol, not a cached
empty-directory observation. Source, boot, session, seat, compositor, output
generation, lock and protected-owner identity must be checked before and
after publication. A concurrent startup, changed process identity or
partial checkpoint refuses.

| Failure point | Mandatory behavior |
| --- | --- |
| Before durable release preparation | Preserve the original fence; no new authority |
| Torn/full/unreadable retirement storage | Fail closed for existing and replacement admission |
| After durable prepare, before native consumption | Keep a single immutable spent/ambiguous operation; no automatic effect |
| During native release or after a lost acknowledgement | At most one native attempt; read-only reconciliation only |
| Frame, input, owner, Root or source proof lost | Hold surviving protection and admission; no optimistic completion |
| Reply lost after independently durable completion | Re-read exact committed lineage and fresh physical state; do not replay native effects |
| Protection-service or compositor restart | Do not reconstruct an old witness, approval, channel or owner from disk |
| Original Committed survives compositor death | Adopt only the independently proved desired state and original ownership, never blindly compensate to baseline |
| Supersession or shared retained checkpoint | Require independently approved successor and owner/reference-aware retirement; never delete-to-retry |

At every boundary, inject native/compositor/Root/executor termination,
concurrent owner and startup requests, interrupted writes, missing ACK,
stale or substituted evidence, hotplug, power/suspend, focus and protected
input. Compare actual per-output completed frames and KMS state, not just
synthetic receipts. A failed repair may retain an indeterminate record but
must never reset a spent one-use release grant.
