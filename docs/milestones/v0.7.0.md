# v0.7.0 — persistent intent lifecycle and local Linura Library

**Status:** released
**Claim class:** Experimental

## Purpose

v0.7.0 adds durable, local, declarative user intent and reusable Linura Library objects on top of the already-qualified v0.6 managed-mutation lifecycle. It does not widen privileged execution authority.

## Capability boundary

v0.7.0 introduces:

- durable intent records with typed requirements and explicit lifecycle state;
- append-only intent revision history with optimistic concurrency and idempotent mutation semantics;
- causal ownership between active intents and resources so retirement can distinguish shared resources, sole ownership and ambiguous ownership;
- revisioned reusable `Setup` and `MachineProfile` Library objects with deterministic composition and cycle rejection;
- versioned portable export/import for Library definitions without exporting local authority or secret values;
- adoption dry-run that reports collisions, missing secret references, machine-class mismatches and unsupported capabilities before any local mutation;
- local backup/restore, schema-version migration, corruption rejection and crash-safe transactional persistence;
- exact-source dedicated v0.7 qualification integrated into Trusted Release Proof.

The Library layer is local and declarative. It may describe desired outcomes, compositions and references, but it cannot create approvals, acquire executor capability, manufacture policy decisions or bypass the v0.6 authorization/verification path.

## Durable intent model

The minimum durable intent record contains:

- stable intent identifier;
- human-authored goal/description;
- typed requirement set;
- lifecycle state;
- monotonically increasing revision;
- creation/update provenance;
- causal ownership edges to resources or desired-state objects;
- operation/idempotency identity for mutation requests.

Supported lifecycle transitions are explicit and testable. Terminal or semantically incompatible transitions fail closed. Stale expected revisions are rejected without partial mutation.

## Causal ownership

Resource retirement must not infer ownership from names, timestamps or filesystem/service presence alone.

For every managed resource considered for cleanup, Linura must be able to determine whether:

- one active intent owns it;
- multiple active intents share it;
- no active intent owns it and cleanup is therefore eligible;
- ownership evidence is incomplete or ambiguous, in which case cleanup is not authorized.

The causal graph remains evidence-bearing state and must survive restart, export boundaries where appropriate, backup and recovery.

## Linura Library

### Setup

A `Setup` is a reusable declarative composition of intent requirements and/or other Setup references. Revisions are append-only. Composition is deterministic, cycles are rejected and prior revisions remain addressable.

### MachineProfile

A `MachineProfile` is a reusable declarative machine-oriented composition that preserves machine-class constraints. A profile can participate in adoption compatibility analysis but cannot itself grant privileged authority.

### Portable artifact

Portable Library artifacts are deterministic and explicitly versioned. They may carry declarative definitions, revisions, stable identifiers and non-secret references. They must not carry:

- approval grants;
- executor capability;
- local policy decisions;
- secret values;
- host-local credentials;
- opaque authority-bearing runtime state.

Import parses and validates the entire artifact before mutation. Unsupported-newer formats, digest corruption, malformed records, cycles and unsafe collisions fail without partial adoption.

## Adoption dry-run

Before adopting a portable Setup or MachineProfile into a local Library, Linura reports at minimum:

- identifier/revision collisions;
- missing secret references without reading or storing secret values;
- machine-class incompatibility;
- unsupported capabilities;
- already-present compatible objects;
- operations that would be required after explicit user approval.

Dry-run itself performs no mutation.

## Persistence and recovery

The local Library uses versioned durable storage with transactional current projections plus append-only history. Qualification covers:

- clean process restart;
- crash between history/projection writes;
- stale-operation replay;
- schema migration;
- corrupt database detection;
- unsupported-newer schema rejection;
- backup/restore validation before replacing the active store;
- preservation of intent lineage, causal ownership and idempotency state.

A failed restore never replaces the valid active database.

## Security and authority invariants

- imported artifacts never restore approval or executor authority;
- secret references are opaque identifiers, never secret values;
- all mutation-capable behavior remains behind the existing v0.6 policy/authorization/executor/verification lifecycle;
- malformed or ambiguous portable state fails closed;
- model/agent output remains untrusted input and receives no authority in v0.7;
- local Library APIs expose declarative state, not a generic privileged execution surface.

## Required qualification

Dedicated v0.7 qualification must prove at minimum:

- durable intent create/read/list/history across restart;
- legal/illegal lifecycle transitions;
- stale revision rejection and idempotent retry/substitution rejection;
- shared/sole/ambiguous causal ownership behavior;
- Setup and MachineProfile revision/composition invariants;
- deterministic export and cross-store round trip;
- corrupt/newer/malformed/cyclic artifact rejection without partial import;
- same-device and cross-device adoption dry-runs report collisions, missing secret references and machine-class compatibility;
- imported artifacts never contain or restore local mutation authority;
- backup/restore round trip preserves all durable Library invariants;
- corrupt/newer-schema backup is rejected without replacing the active valid store;
- crash/failure injection around transactional writes produces either the old complete state or the new complete state, never a partial projection/history pair;
- canonical CI, Security and CodeQL pass on the exact candidate;
- Trusted Release Proof incorporates the dedicated v0.7 qualification before publication.

## Explicit non-claims

v0.7.0 remains Experimental. It does not claim Stable or production support, a supported Linux distribution/machine profile, hosted Library sync, remote fleet authority, arbitrary package/file/network mutation, generic systemd management, unattended agent authority, secret synchronization, multi-machine atomicity, or a generic privileged execution surface.
